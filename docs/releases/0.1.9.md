# Farport 0.1.9（构建 12）

## Codex 宠物

- 普通本地和 POSIX SSH 终端可显示 Codex 内置宠物动画；新开终端运行 `codex`，用 `/pets` 选择，`/pets off` 关闭。
- Kitty 内嵌图像与 Sixel 已通过实际像素渲染测试。Codex CLI 0.163.0 的内置 Rocky 在本机、隔离 Linux SSH 均通过连续帧和选择器验收。
- 使用 `Farport-Kitty` 标识声明自身与 Kitty 协议兼容，保持 `TERM=xterm-256color`，不安装远端组件或修改登录配置。原生 Windows SSH 仍使用默认 Shell，不套用 POSIX 登录命令。
- tmux 页增加普通终端入口。Codex 官方目前禁用 tmux/Zellij 内宠物；这项限制不绕过，原 tmux 会话不结束。

## 图像安全与边界

- 只接受 Kitty 内嵌图像，阻止读取或删除宿主文件、共享内存，限制图像尺寸、分块传输大小与缓存。
- 验证图像删除/替换、备用屏幕退出、UTF-8 分包、过长和异常协议恢复；保留上一版预览服务闪退修复。
- 自定义宠物格式必须与所用 Codex CLI 版本兼容。此次不修改自定义素材、不附带 Codex，也不依赖用户的 API 密钥进行测试。
- 新功能作用于新建终端，不会自动断开已有会话。

提供 Apple Silicon、Intel、Universal 三种 DMG/ZIP。Apple Silicon 完成运行验证；Intel 完成构建和安装包检查，未新增 Intel 真机测试。仍为 ad-hoc 签名，未 Apple 公证。

## English

Regular local and POSIX SSH terminals can now render Codex pets. Start Codex in a new terminal and use `/pets`. Tested with real Codex CLI 0.163.0 and its built-in Rocky on macOS and Linux SSH. Farport identifies itself as `Farport-Kitty` while keeping `TERM=xterm-256color`. Native Windows shells are not replaced. Kitty inline images and Sixel render normally; file/shared-memory image transports are blocked and image sizes, transfers and cache are bounded. Codex's tmux/Zellij restriction remains in effect; a regular-terminal action is available without closing tmux sessions. Custom pet assets must match the CLI's format. Previous fixes remain included.
