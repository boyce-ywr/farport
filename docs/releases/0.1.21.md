# Farport 0.1.21（构建 27）正式版

## 新功能（预览）

- **内嵌远程桌面第一期**：基于自研 RFB（VNC）客户端，桌面以终端标签形式打开，可以弹出为独立窗口或全屏。默认通过 `ssh -W` 经 SSH 承载，也可以按主机改为直连，直连时会标明未加密。支持 VNC 口令和 macOS 账号（ARD）认证、键盘映射、鼠标与触控板滚动，以及文本剪贴板双向同步。口令保存在 Farport 专用的钥匙串条目中，认证失败不会自动重试。
- 远端为 macOS 屏幕共享时，均衡档和流畅档改用 16 位色，低带宽下帧率约提升 2–3 倍，并修复了拖影。直连被本机网络过滤拦截时，会提示改用经 SSH 连接。详见 [卡顿复盘](../issues/2026-11-03-远程桌面经SSH连macOS卡顿.md) 和 [直连拦截复盘](../issues/2026-11-03-远程桌面直连EBADF被网络过滤拦截.md)。

## 修复

- **远端 tmux 会话识别不出来、新建时报 `duplicate session`**：远端为 tmux 3.3 且通过 SSH 远程执行命令时未设置 locale，tmux 会把输出中的 Tab 替换成 `_`，导致会话列表为空。现在所有 tmux 命令都加上 `-u`。这个问题也会影响附件插入前的窗格核对，已一并修复。详见 [问题复盘](../issues/2026-11-08-远端tmux3.3无locale时会话列表为空.md)。
- **普通本机终端里运行 docker 容器时，附件被发送到 Mac**：以前只有 tmux 窗格会识别 Docker。现在普通本机终端的前台进程是 `docker exec -it` 或 `docker attach` 时，也会识别对应容器并把附件发送到容器内，插入路径前会再确认前台仍是同一个 docker 进程。前台不是 docker 时，仍发送到本机。

功能提交：`1b905eb`、`8812b74`、`a04591c`。

## 使用边界

- 远程桌面仍是预览：macOS 屏幕共享只提供 ZRLE/Raw 无损编码，低带宽下仍比系统屏幕共享慢；Tight 画质档对 macOS 远端无效。
- 普通本机终端的 Docker 附件只覆盖本机 docker 客户端。终端里先 SSH 到其他机器、再在那里运行 docker 的情况，仍不能自动识别。
- **仍为 ad-hoc 签名，未完成 Developer ID 签名和 Apple 公证。** Intel 版只做了交叉构建和静态验证，没有在真机上运行验证。
