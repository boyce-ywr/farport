# Farport 0.1.24（构建 30）正式版

发布状态：待发布（本地构建与验证完成后更新）。

## 新功能

- **会话页支持 Zellij 和 herdr**：原“tmux 会话”页改名“会话”，自动检测主机上安装的 tmux、Zellij（0.44 及以上）和 herdr（0.9 及以上），按工具分组列出会话和窗格。本机和 SSH 主机（需 POSIX Shell）都适用。
  - Zellij 显示标签、窗格命令和目录；herdr 显示工作区、标签、目录，以及它识别到的 Agent 和状态（如 `claude · working`）。
  - 新建会话：Zellij 在后台创建；herdr 会打开一个终端标签，在其中创建并进入会话。
  - “结束会话…”会终止会话里的全部进程（包括 Agent）并删除记录，需要确认。关闭终端标签只是分离，会话继续运行。
  - Zellij 已退出、herdr 已停止的会话单独列出，只能删除。Farport 不提供“恢复”，因为 Zellij 的恢复会重新运行记录的命令，而不是继续原来的进程。
  - herdr 不支持重命名会话，菜单项置灰并说明。
  - 没安装的工具在页底注明，版本过低会提示并停用相关操作。Farport 不会自动安装或修改配置。
- **连接时进入**：主机设置中原来的“连接时优先打开 tmux 工作区”改为“连接时进入：普通终端 / tmux / Zellij / herdr”。以前勾选过 tmux 的主机自动对应 tmux；降级回旧版本时，选了 Zellij 或 herdr 的主机按普通终端连接。零个会话询问新建，一个直接进入，多个让你选择。
- **复制**：在 Zellij、herdr 里用它们自己的鼠标选区复制，内容经 OSC 52 交给 Farport，按“终端剪贴板”权限写入 Mac 剪贴板。仍可按住 Shift 拖选使用 Farport 本地选区。

功能提交：`1101d33`。设计决策和实测记录见 [调研文档](../research/2026-11-11-Zellij与herdr会话支持.md)。

## 使用边界

- 在 Zellij、herdr 窗格里粘贴附件、Cmd+点击路径，目前按普通终端处理：发往所附着的主机，还不识别窗格内的 Docker 容器。计划在后续版本支持。
- macOS 上 Zellij 的会话名超过约 24 个字符时可能因 socket 路径过长而创建失败，Farport 会直接显示 Zellij 的报错。
- Windows 原生 Shell 的 SSH 主机不支持这三种工具。
- **仍为 ad-hoc 签名，未完成 Developer ID 签名和 Apple 公证。** Intel 版只做交叉构建和静态验证，不在真机上运行验证。

## 验证

- 开发构建：2966 项核心断言，包括 Zellij/herdr 输出解析、名称校验、旧配置兼容和环境变量隔离。本机 Zellij 0.45.1、herdr 0.9.5 服务层实测通过。
- 真实 App 端到端（中英文 × 本机/回环 SSH 模拟远端 Mac）：会话检测、终端附着（经 Zellij 客户端列表确认）、关闭标签只分离、herdr 在终端内新建、连接时自动进入 Zellij、结束会话后记录删除，全部通过。Zellij、herdr 鼠标拖选经 OSC 52 写入 Mac 剪贴板的实测通过。
- 未验证：Linux 远端主机上的 Zellij/herdr、Zellij 0.44 实机。依赖 Docker SSH 夹具的首选 tmux 界面回归本次未运行（本机缺少测试镜像），其本机 tmux 模型部分通过。
