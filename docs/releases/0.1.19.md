# Farport 0.1.19（构建 25）正式版

2026-10-29 准备发布。正式包验收、草稿附件、公开下载和在线更新尚待核验，不等同于已公开发行。

## 新功能与修复

- **Claude Code 等全屏程序的复制**：程序自己处理鼠标选区时（如 Claude Code 全屏界面），选区不在 tmux 复制模式中。现在 ⌘C 会读取本次按下鼠标之后由程序新建的 tmux 缓冲区。按下鼠标前就存在的旧内容不会被误取，也不依赖两台机器的时钟。
- **容器内程序的复制**：docker 容器里没有 `TMUX` 环境变量，Claude Code 只能发 OSC52，tmux 默认的 `set-clipboard external` 会把它丢弃。⌘C 读不到内容且窗格在容器或嵌套会话中时，Farport 会请你确认是否开启接收；开启只影响当前运行的 tmux 服务，不修改配置文件，写入 Mac 剪贴板仍按终端剪贴板权限处理。
- **远端 tmux 中 Docker 的截图与附件**：SSH 主机的 tmux 窗格运行 `docker exec`（如 docker-claude）时，会经 SSH 识别原窗格的容器，把文件复制到容器内、核对内容和读取权限后插入容器内路径，不自动回车。之前这种情况会提示“窗格可能处于嵌套环境”并拒绝发送。
- **识别出容器时不再要求选择**：能从原窗格的 docker 命令确认容器时直接上传并插入；参数无法解析但只有一个运行中容器时使用该容器。本机 tmux 的 Docker 同样适用。
- **Shift 拖选不再被输出打断**：按住 Shift 拖选或已有本地选区时，窗格的持续输出不再清除选区。

## 性能与使用边界

- 远端 Docker 图片附件经本机回环 SSH 测量（Debug 构建、小图）：“摄取到插入”第 1/2 轮约从 17.4/10.8 秒降到 4.2/3.3 秒；本机 Docker 首次约从 7.6 秒降到 6.0 秒。不代表任意大小图片、网络和机器的固定时延，也不包含 Agent 后续读取和识别。
- 远端为 macOS 时，docker 命令参数由 `ps` 按空格切分；容器名或工作目录含空格可能识别失败，此时仅在只有一个运行中容器时回退，否则明确报错，不会发到错误容器。
- 开启的 `set-clipboard on` 在 tmux 服务重启后失效，需要再次确认，或自行写入 tmux 配置。
- 未在实际 mac-mini 上验证；远端链路以本机回环 SSH 加真实 docker 容器和真实 Claude Code 代替。
- 远端容器暂不支持在 Farport 中直接打开 Agent 终端。
- **仍为 ad-hoc 签名，未完成 Developer ID 签名和 Apple 公证。** Intel 只做交叉构建和静态验证，不代表真机运行通过；新复制安装目录的运行限制不在通过声明内。
