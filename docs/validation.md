## 图形验收状态

原生开发程序和打包后的 ARM Debug 版本均已实际启动并建立 SSH 连接。初始截图暴露了状态观察与离屏透明层采集问题，已修复；原始问题图仅保留在 `docs/issues/artifacts/`，不冒充最终验收图。

最终 ARM Release 原生程序完成 11 张实际视图快照：终端、tmux、文件、传输的浅/深色各一张，双主机分屏、真实 tmux 附着、小窗口文件布局各一张。文件位于 `docs/screenshots/`，每张旁边的 JSON 记录实际页面、尺寸、采集方式和终端状态。截图脚本使用独立测试数据；页面不匹配、终端未连接或没有窗口时返回失败，避免旧图片被当成新结果。标准窗口为 1360×860，小窗口快照为 980×672（含窗口框架）。

当前没有系统屏幕录制授权，快照通过应用自身的原生视图缓存获得；终端区域合成其真实背景图层，没有重画终端文字。它证明实际界面可渲染，不等同于全套鼠标、输入法、显示器和辅助功能人工验收。

**发行阻塞仍存在：**最终 Universal 包已复制到 `~/Applications/Farport.app`，磁盘上的完整签名校验通过，但直接启动与 LaunchServices 启动均未成功。2026-10-13 14:19 的运行采样显示进程为 ARM64、物理内存仅 96 KiB，全部样本停在 `_dyld_start + 0`；之后进程以 137 退出，尚未进入应用业务代码。日志同时有 ad-hoc/未知证书链提示和公司安全组件进程标签，但相同提示也出现于成功的 Debug 包，**因此不足以断言具体哪一组件是根因**。

本机没有可用 Developer ID 签名身份。未关闭防护、修改安全数据库或伪造 bundle identifier；产品改名来自用户的命名需求，应用身份一直保留 `local.sshworkbench.mac`。当前保留用户正在运行的已有开发包窗口，不强制退出它。下一步需要用户通过正常系统界面打开安装包，提供具体的拦截提示，再决定合法的允许运行、签名或 IT 排查路径。
