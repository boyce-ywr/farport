# Farport 竞品调研与产品优先级

核查日期：2026-10-19。范围：桌面端个人开发者的 SSH 工作流，特别是远程 Mac。状态：研究与设计建议，不是功能已交付清单；本轮未修改产品代码、构建或安装应用。

后续进展：用户再次确认后，开始落地首批工作工具与实验性 Mac 桌面入口。本文保留调研时的基线和优先级；实际实现、使用方法及验证边界见 `../工作工具首批使用说明.md`。

## 结论与证据口径

产品方向建议：围绕同一台远程主机，把终端、文件、常用命令、端口和 Mac 桌面连接起来，减少重复操作。优先做可靠的日常工作工具，不先做全协议远控、云账号平台或自动执行命令的 AI 助手。

“高频”在这里是待验证的工作流假设，不是市场调查结果：官方文档能证明竞品提供什么，原始 issue 能证明具体人遇到过什么，均不能推算市场使用率。优先级综合本项目用户已反馈的问题、日常工作步骤、现有实现基础和失败成本；没有虚构用户数、付费意愿或百分比。

## 竞品带来的有效启发

| 产品 | 一手资料中的能力 | 对 Farport 的启发与限制 |
| --- | --- | --- |
| Termius | 官网介绍工作区恢复、SFTP、Snippets [S1] | 少重复建连接、找命令；不能把工作区恢复等同远端进程保活 |
| SecureCRT | 命令管理器可分组、筛选和启动命令，支持会话布局快照及日志 [S2] | 优先命令快速找到、环境识别、会话恢复，而非增加协议数量 |
| MobaXterm | SSH 旁的图形 SFTP 浏览器、多会话、多目标执行 [S3] | 减少终端与文件工具切换；不照搬整个 Windows 工具箱；广播有误操作风险 |
| iTerm2 | Shell Integration 提供远端目录、命令历史等上下文 [S4] | 目录联动、历史、完成通知可共用上下文能力，但需要支持的 shell/远端集成，不能解析提示符猜状态 |

另补充 Wave Terminal、WindTerm 的官方资料，具体证据与适用边界见同目录 `2026-10-19-additional-terminal-products.md`。这些产品是本轮新增研究对象，不代表新发布产品，也未进行竞品安装体验或性能对比。

社区原始反馈见 `2026-10-19-ssh-community-signals.md`：包括重连不等于恢复原会话、命令缺少快速入口、保存远端文件后丢执行权限、目录联动的环境前提、广播输入语义不一致。历史 issue 的关闭状态不等于本轮已验证当前版本行为。

## 本地现状：不要重新造已经存在的功能

本轮仓库 HEAD 为 `28cd90d`；以下结论来自本地代码，而不是在线最新发行状态。

- 已有手动重连和 tmux 入口；`Sources/WorkbenchApp/TerminalSession.swift` 的 `reconnect()` 重新启动连接，不等于完整工作区恢复。
- 已有文件浏览、回退历史、编辑和冲突检查；`Sources/WorkbenchCore/DirectoryHistory.swift` 的历史上限为 100 条。不能把“跟随终端来源”描述成“跟随当前目录”：`TerminalSession.swift` 的 `hostCurrentDirectoryUpdate` 当前为空。
- 已有端口转发：`Sources/OpenSSHBackend/SSHTransport.swift` 的 `forwardingArguments` 以及 `Sources/WorkbenchApp/TunnelWorkspace.swift`。新增方向是模板与连接工作流，不是从零实现隧道。
- 已有本机剪贴板写入/回读反馈和远端复制授权：`Sources/WorkbenchApp/TerminalClipboard.swift`。不再把“支持复制粘贴”列为新功能，而应检验发行包、焦点、tmux/TUI 和远端复制的真实体验。
- 本轮针对应用层的检索未找到命令片段中心、跨启动完整工作区恢复或结构化命令历史实现；这是代码审查范围内的缺口，不宣称远端 shell 没有历史功能。
- 发行验收必须区分版本：`docs/issues/2026-10-16-新版安装验收.md` 记录 0.1.8 安装启动通过；`docs/issues/2026-10-16-终端复制反馈与进程表头排序.md` 仍保留 0.1.10 预发布的安装版启动限制。本轮没有重跑安装验收，不能断言当前仍必现，也不能把一个版本的通过当成另一个版本已经解决。

## 推荐顺序

### P0：可靠性与交付门槛，先于扩大功能面

把闪退、剪贴板和发行版安装验收作为门槛，不是再做一次功能宣传。覆盖复制真正写入系统剪贴板、无选区不清空已有内容、tmux/TUI 选区、后台远端复制不覆盖前台内容、预览频繁开关、休眠唤醒、最终安装包启动。

验收要求：测试说明应用版本、实际运行路径、场景与结果；不能用 Debug 或独立二进制测试代替最终安装包，也不能用“已建立连接”代替对应业务功能验收。

### 第一批：三项通用工作流改进

| 方向 | 用户实际得到什么 | 首期边界 | 核心验收 |
| --- | --- | --- | --- |
| 工作区恢复与清晰重连 | 打开应用找回主机、标签和分屏；断线后知道如何继续 | 先保存布局与连接意图；重连需保持主机指纹检查；只恢复已选择的 tmux，会话不存在不偷偷换成新会话 | 应用重启、断网、休眠后不串主机，不重放命令；普通 SSH 与 tmux 的恢复能力明确区别 |
| 终端—文件目录联动 | 终端进入项目目录，文件区可跟随；目录可收藏、快速返回 | 先手动“定位文件区”；自动跟随可开关；优先消费可信会话的目录报告，缺少远端集成时明确降级 | 路径有空格/中文也正确；分屏、嵌套 SSH、sudo、tmux 场景不把路径套给错误主机 |
| 常用命令中心 | 快速找出看日志、检查服务、进入项目等常用命令 | 从手动保存的片段做起，支持名称/标签/适用主机；默认插入待执行，不收集所有输入或自动敲回车 | 正确目标可见、粘贴不会意外执行、参数引用明确；用户可删除记录，不收录密码输入 |

这些是建议范围，不是三套庞大系统：完整命令历史、自动远端配置、全量输出存档、自动恢复端口/VNC 会话都不混入首期工作区恢复。

### Mac 专项：一键打开远程桌面

用户已接受推荐方向：Farport 管理入口和独立 SSH 隧道，macOS 系统 Screen Sharing 负责显示、输入及认证。首期针对远端 Mac 已授权系统用户，不要求另设传统 VNC 共享密码；不等同于 Apple Account/iCloud 登录。[A1][A2]

这是远程 Mac 用户的重点能力，不能推为所有 SSH 用户的普遍高频需求。首期标准屏幕共享；内嵌渲染和高性能模式不纳入普通 TCP SSH 隧道承诺。[A3；工程判断]

必须先完成小型真机验证：禁用共享 VNC 密码后使用 Mac 系统账户连接；直连与 SSH 各测；同时连接两台主机不串凭证；终端关闭不误断桌面；隧道释放不影响其他连接。详见 `2026-10-19-Mac远程桌面设计建议.md`。

### 第二批：少量投入、明确收益的延伸

1. **隧道模板＋打开远端 Web。** 在已有端口转发上保存目标/端口/用途，例如远端开发 Web 或 Notebook 服务；一键建立通道后打开浏览器。仅绑定 loopback，保留服务自身认证，不把带 token 的 URL 写入日志，不默认恢复公网监听。对远程开发可能比内嵌 VNC 覆盖面更广，这是待验证假设。
2. **远程编辑差异预览。** 复用现有编辑器和冲突检查，补保存前 diff、保存失败后的本地草稿与明确重试；验证权限保持。先减少误覆盖，不扩展成 IDE 或通用合并器。
3. **长任务完成提醒。** 从已能可靠获知结束/退出码的任务做起；终端命令需 shell 集成后再做。不用屏幕停止输出猜完成，不默认保存完整敏感命令或输出。
4. **按命令复制，而不只靠拖选。** 在可靠的命令边界集成之后，增加“复制这条命令”“复制这次输出”；显示复制范围，保留合理换行，不夹入提示符/终端控制序列。没有边界信息、输出已经被滚动缓冲淘汰或位于不支持的全屏程序时明确不可用，退回现有选区复制；不凭屏幕外观猜完整输出，也不为此默认落盘所有终端内容。

## 三个贯穿交互的优化

- **目标一直看得见。** 终端、文件、隧道和桌面入口共享清晰的主机名/账号/环境标记；生产环境提供持久标识，避免只靠颜色区分。命令片段及未来广播都显示目标。
- **反馈描述真实结果。** 区分请求发出、通道就绪、文件已保存、复制成功；不能把进程启动当作桌面登录成功，不能把远端程序打印的 Copied 当作本机剪贴板已更新。
- **减少打断但保留风险确认。** 常见操作用非模态状态提示；首次远端剪贴板授权、危险覆盖、关闭有任务的连接保留清晰确认。取消操作与资源释放要一致，不增加一排长期占位的面板。

## 暂不优先

- AI 自动执行命令、独立 AI 聊天栏：先解决复制、会话与上下文，避免增加数据外发和误执行路径。
- 全协议远控/全平台客户端、第一版内嵌 VNC：会放大渲染、输入、认证、许可与测试范围。
- 云同步/团队密码库：未确认当前用户确有协作需求；安全、权限、同步冲突不应顺手扩展。
- 多机广播：确有竞品和社区需求证据，但当前本项目没有多机批量操作规模证据；日后需目标锁定、明确退出、危险命令确认等设计。

## 不靠猜测验证下一轮优先级

用本机自愿参与的工作流验证，不先加默认遥测：准备固定的“重开工作区、找项目目录、复用命令、开远程网页、连远程 Mac”任务，记录操作步骤、是否中断、失败原因；改进前后同场景比较。先检验节省了什么，再考虑扩展。
