# 终端标签快捷切换与 Agent 会话面板设计

日期：2026-10-20。状态：设计草案，尚未实施；需在当前 Docker 附件功能收尾后进入开发。本文件区分现有源码事实、官方工具能力与产品建议，不把计划当作完成。

## 1. 目标与非目标

覆盖四个高频动作：快速切换 Farport 外层标签、找回同设备上的 Claude Code/Codex/Pi 工作、打开对应目录、继续明确的历史会话。用户不必记工具参数、会话 ID 和工作目录。

不做新的 Agent 对话客户端，不托管模型请求、不自动升级/安装 Agent，不全文索引聊天、不跨机器搬运会话、不自动重放指令。不把 SSH 连接恢复、tmux 进程仍在、Agent 历史恢复混称为“恢复成功”。

## 2. 现有实现与复用点

- `Sources/WorkbenchApp/SSHWorkbenchApp.swift` 已有 `⌘⇧[` / `⌘⇧]` 上下标签、`⌘[` / `⌘]` 分栏；`⌘1–6` 已用于工作页，不能直接照搬其他终端的 `⌘数字` 标签定位。
- `Sources/WorkbenchCore/TerminalLayout.swift` 已实现标签顺序、循环选择、记忆标签内活动分栏。新快捷键调用现有动作，不另建标签状态。
- `Sources/WorkbenchApp/SessionTabs.swift` 已有标签点击和标签列表搜索，应该复用其列表，而不是增加另一套标签查找弹窗。
- `WorkspaceSnapshot` 当前保存连接身份、tmux ID 和布局，不保存 Agent ID、会话目录、工具版本；恢复工作区不等于恢复 Agent 历史。
- `Workspace.insertSnippet` 只插入命令、不回车，并检查目标及 alternate buffer；这不足以证明前台是空闲 Shell，不能直接升级为自动执行 Agent 恢复命令。
- `TerminalSession.reportedDirectory` 对普通 Shell 接收可信 OSC 7，对 tmux 明确不采信。会话面板需增加 tmux 原窗格目录探测，不能以旧缓存或应用 cwd 代替。
- 当前 Docker 附件开发已有前台进程、context、容器 ID/启动状态/用户绑定的识别思路；Agent 会话应复用已确认的执行目标，不把“此 Mac”误当成容器内环境。

### 竞品借鉴与不照搬的部分

本轮新核验三个竞品；详细官方正文、抓取范围与 URL 在 `docs/research/2026-10-20-terminal-session-competitors.md`。此前 Wave/WindTerm 的工作区研究见 `docs/research/2026-10-19-additional-terminal-products.md`，不将旧资料当作本轮重新实测。

| 参考 | 已核实的交互事实 | Farport 的取舍 |
| --- | --- | --- |
| iTerm2 | `⌘数字` 默认选择标签且可改修饰键；Open Quickly 按标题、主机、目录等定位终端；Profile 可指定起始目录 | 借鉴可搜索入口和目标目录信息。Farport 的 `⌘数字` 已用于工作页，改用 `⌘⌥数字`；Profile 不能冒充 Agent 历史会话 |
| Ghostty | 标签导航动作与 consumed/unconsumed 的按键消费语义明确区分 | 借鉴应用动作消费按键。这里不能启用“动作成功且同时透传”；单标签 no-op 也不发送保留导航按键 |
| Zellij | session resurrection 重新创建布局并运行记录的命令，默认有执行确认，且命令发现并非始终准确 | 借鉴可运行与已退出记录分组；不照搬命令重放作为 Agent 恢复，只恢复工具明确支持的会话 ID |

结论：不是照抄另一款终端，而是把 iTerm2 的查找入口、Ghostty 的输入消费规则和 Zellij 的恢复状态区分，组合为 Farport 的“同执行目标找回工作现场”。这些事实不证明任何竞品已经具备三种 Agent 的统一会话索引。

## 3. 功能一：外层标签导航

### 默认按键建议

| 动作 | 新增默认 | 兼容与范围 |
| --- | --- | --- |
| 上一个/下一个外层终端标签 | `⌘⌥←` / `⌘⌥→` | 保留 `⌘⇧[` / `⌘⇧]`；按屏幕顺序循环 |
| 定位前八个标签 | `⌘⌥1…8` | 不占用现有 `⌘1–6` 工作页切换 |
| 定位最后一个标签 | `⌘⌥9` | 数字在当前窗口的外层标签内解释 |
| 分栏切换 | 保留 `⌘[` / `⌘]` | 不改变已有含义 |
| 查找 Agent 会话 | `⌘⌥J` | 建议值，开发前统一做菜单/系统/键盘布局冲突检查 |

不默认接管 `Ctrl+B`、`Ctrl+A`、`Ctrl+数字`、`Alt+数字`、`Ctrl+Tab`。这些组合可能属于 tmux 或终端程序，不能以“传统终端不识别某组合”推断没有冲突。

本轮静态检索未发现推荐新增组合与 Farport 当前绑定重复；这不包含系统快捷键、自定义键盘映射或实机验收。禁止泛拦所有 `⌘⌥`：`⌘⌥S` 已用于侧栏，锁定 SwiftTerm 还包含 `⌘⌥O` 的 Option-as-Meta 开关，只拦精确注册的导航组合。

### 事件与体验规则

1. 本地导航只在当前 Farport 工作窗口、终端页且终端内容有焦点时启用。文本编辑、IME 组合输入、搜索弹窗、sheet/modal 保留各自按键语义，不抢焦点。
2. 被接管的完整按键生命周期留在应用侧：keyDown、连发、对应 keyUp 不能因为切换了标签而泄漏给新旧 PTY。不能依靠“有 Command 所以一定不进终端”；现有 SwiftTerm 的增强键盘协议可能编码 Super。
3. 单标签和不存在的数字目标是本地 no-op，不把保留导航按键变成终端输入。未知组合继续按原路径处理。
4. 不影响 SSH 连接和 tmux 会话；切回标签恢复它此前的活动分栏。标签 tooltip 和菜单展示快捷键，按住 `⌘⌥` 可作为后续提示增强，不阻塞首版。
5. 初版不做全量按键编辑器。后续若开放重新绑定，明确“由 Farport 消费”的含义，避免与其他应用动作重复；用户若选择终端透传，就不能同时承诺该键导航且不冲突。

## 4. 功能二：当前执行目标的 Agent 会话面板

### 入口与界面

放在“工作工具 → Agent 会话…”并提供 `⌘⌥J`。使用可关闭的搜索面板，不新增常驻顶层工作页；键盘优先，但每个动作都可点击。

```text
Agent 会话                                    此 Mac → Docker · dev · tester
搜索：项目、工作目录、会话名称、ID
[全部工具] [Claude Code] [Codex] [Pi]         [当前目录优先] [刷新]

正在运行 / 可定位
  Claude Code   farport      ~/projects/farport    [切回终端]

最近会话
  Codex         修复文件复制 ~/projects/farport    20 分钟前
  Pi            日志检查     ~/projects/ops        昨天

详情：工具、会话 ID、目录、目标设备/用户、最后更新、可用动作
[打开工作目录] [在新标签中恢复] [在此目录新建会话]
```

默认仅当前执行目标和当前用户，不扫描所有保存主机、不自动 SSH 到离线主机。当前目录匹配项优先，但不默认隐藏同设备其他项目；用户可显式切换“只看当前目录”。

标题优先使用工具提供的命名/摘要字段；没有标题时用项目名、时间、短 ID，不为了标题默认读取第一条用户提示或调用模型生成摘要。目录名称和工具内容都是数据，不是可执行指令。

### “设备”的精确定义

- 本机：系统用户 + 已确认的 CLI 安装/数据根目录。
- SSH：连接身份（包括地址、端口、用户名及影响连接身份的配置）+ 目标用户。读取发生在远端，不去扫描本机同名目录。
- Docker：本机 context/daemon 身份 + 完整容器 ID + 启动代次 + 容器用户；只在可识别且已确认的目标上列举。容器重建不按名称自动重新绑定。
- 手动二次 SSH、容器内再切用户、未知 wrapper：显示“目标环境未确认”，允许配置实际连接，不静默回退到宿主机。

当前面板打开后固定执行目标快照；后台切标签不能让列表突然变成另一台机器，更不能让搜索结果在新目标执行。提供清晰的“切换到当前终端目标”动作。

### 三类记录，不把猜测显示成状态

| 类型 | 可展示证据 | 默认动作 |
| --- | --- | --- |
| 正在运行且可精确定位 | Farport 登记的工具进程/Agent ID，或可校验的 tmux pane 映射 | 切回原标签/分栏或附着原 tmux，不再启动第二个 Agent |
| 工具记录中有历史会话 | 工具/版本允许读取的会话 ID、cwd、更新时间；运行状态可能未知 | 在新标签启动该工具的精确恢复命令；存在活动实例证据时先提示 |
| 不可恢复/不可判定 | CLI 未安装、格式不支持、目录/文件丢失、权限不足、目标失效 | 给具体原因；可打开目录或工具原生选择器，不虚构 ID 或新建替代 |

仅发现会话文件，不等于对应进程已经停止；仅发现同工具进程，不等于它正在使用某条会话。未知就是“运行状态未知”，不能标成“已停止”。

### 关键动作语义

1. **切回运行中会话**：已有 Farport 位置优先定位并聚焦；同设备 tmux 位置明确时附着。其他终端应用中的普通 TTY 不能凭 PID 无损接管，提示其位置，不自动重复恢复。
2. **恢复历史会话**：默认在同执行目标的全新 Farport 标签启动，使用明确会话 ID/路径和正确工作目录。不要向正在对话的 Claude Code/Codex/Pi、Shell 前台任务或容器 TUI 发送 `cd`/恢复命令。
3. **打开工作目录**：默认新建同目标 Shell 标签并设置启动 cwd；也可在文件页定位。只有可靠确认当前终端位于可输入的 Shell 提示符时，才开放“在当前 Shell 切目录”；否则仅插入但不回车或新开终端。
4. **新建会话**：明确工具和项目目录；与“恢复”分开。恢复目标不存在/命令失败时禁止悄悄降级为新会话。
5. **通用兜底**：工具没有可靠外部索引时，面板显示“在该设备打开工具原生会话选择器”，在新标签执行，保留可用性但不声称统一列表已覆盖。

恢复动作是用户明确点击的进程启动授权，可在新建进程内直接执行已校验的工具参数，不要求再手工回车；既有终端内普通命令插入仍保持现有“不自动回车”规则。

快捷键面板内建议：上下键选条目、Enter 执行该条目的主动作（正在运行时为定位，历史时为新标签恢复）、`⌘Enter` 在同目录新开 Shell；动作文字始终可见，搜索框 Enter 不执行第一段不明确的命令。首次恢复提示一次目标/工具/目录/会话确认卡，之后相同目标且参数未变才可简化。

## 5. 工具适配与模块划分

三种 Agent 分别建立 Adapter，不能用同一个目录 glob 或把 JSONL 全当作统一协议。官方 CLI 能力优先，其次是带版本门槛的本地索引读取；不存在稳定外部接口时提供原生选择器兜底。确切命令、文件格式和支持版本见配套工具调研，未核实前不写进产品默认配置。

### 本轮官方事实对方案的约束

三工具资料已整理于 `docs/research/2026-10-20-agent-session-discovery.md`，包括精确官方 URL、固定源码、能力版本和未实机验收边界。本方案调查的 Pi 是原 badlogic/pi-mono 的 coding agent 项目，不是 Inflection Pi；实际设备仍需识别安装的命令/版本，不能假定名称相同就兼容。

| 工具 | 已核实能力 | Farport 首版采用方式与约束 |
| --- | --- | --- |
| Codex CLI | 官方 app-server 有 `thread/list`、`thread/read`、`thread/loaded/list`，CLI 有 `codex resume` 和 `codex resume <thread-id> --cd <cwd>` | 优先查询已有且正确的服务；能力支持时采用 `useStateDbOnly:true`、`includeTurns:false`，只消费允许的字段。新启服务可能有初始化副作用，需明确授权或降级到原生 picker；不实现 SQLite schema 解析。恢复使用 thread ID，不把 session tree 根 ID 当当前线程 |
| Claude Code | 官方 SDK 有 `list_sessions/get_session_info`，较新 CLI 有 `agents --json`；CLI 按 ID 用 `claude --resume <session-id>` | SDK 的历史与 CLI 运行态分开。SDK 可能读取 transcript 片段，不能称为“完全不读正文”；默认保留纯原生 picker，用户开启本机/目标侧历史索引后才采用此读取路径，并仅返回选定元数据 |
| Pi coding agent | 官方 SDK 有 `SessionManager.list/listAll`，CLI picker 为 `pi --resume`，精确历史为 `pi --session <file-or-id>` | SDK 列表会读取正文且可能创建目录，不能默默作为只读扫描器启动；首版提供原生 picker和已确认 ID/路径恢复，历史索引开关经授权后再启用。跨项目 ID 可能进入 fork，首选已核实绝对 session 文件路径；保留记录 cwd，不假定启动前 cd 能覆盖 |

共用要求：`list`、`read`、`resume`、`turn/start` 分别代表不同操作，列表展示不触发恢复或模型请求。已有服务的“已加载”状态只代表该服务，不能推断整个设备是否运行另一份相同历史。

**对用户体验不缩水的兜底**：首版三种工具都提供“在当前项目新建”“打开该工具的会话选择器”“打开历史目录”入口；统一历史表只展示已可靠获得的记录。依赖不满足显示对应工具的原生入口及原因，而不是隐藏整个工具或假装设备上没有历史。是否安装 SDK/helper 必须单独授权，不为了列表暗中安装依赖。

建议三个 Module 即可，不建立插件平台：

- `ExecutionTargetResolver`：返回已验证执行目标、cwd 证据及失效原因，复用 SSH/tmux/容器检查。所有业务入口共用相同身份语义。
- `AgentSessionCatalog`：Interface 为发现工具能力、分页列举/搜索、刷新；内部是 Claude Code/Codex/Pi 三个 Adapter 和有限缓存。隐藏文件布局差异、版本检查与权限失败，不让 View 拼路径。
- `AgentSessionLauncher`：Interface 为检查动作并生成结构化启动计划、在新标签执行或定位运行位置。校验参数、目标、cwd、工具可用性和重复启动；不暴露一条由标题字符串拼出来的 shell 命令。

记录标识采用“执行目标身份 + 工具 + 工具数据根 + 原生会话 ID”，不能只按目录/标题去重。列表数据和执行权限分开，读取列表不授予写会话文件的权限。

目录切换/工具启动在本机使用 argv/显式 cwd；远端采用现有安全引用和固定命令模板；容器通过同一用户的新 exec TTY。全程不追加 `--dangerously-*`、权限跳过或其他自动批准参数。

## 6. 性能、隐私与失败恢复

- 按用户打开面板才扫描，首次显示最近最多 100 条（设计起点，不是已测容量），支持后续分页。先返回缓存并标更新时间；后台刷新可取消，超时反馈而不是清空列表。
- 性能目标分层：缓存命中时约 200 ms 内可交互，冷启动先显示扫描进度；远端不承诺固定时延，超过约 5 秒显示已完成项和取消入口。任何目标数值都要在真实大目录/慢链路测量后才能写成性能承诺。
- 默认不发模型请求、不向本机传送远端正文、不全文建索引、不统一拷贝远端会话数据库、不保存认证环境。需要目标侧 SDK 读取 transcript 的适配路径，必须说明并征得开启历史索引的授权；“只展示元数据”不能宣传为“底层绝不读取正文”。
- 新建启动产生的会话记录不由 Farport伪造；启动命令成功只显示“恢复命令已启动”，确认工具报告正确会话后才显示“已恢复”。无可观测确认时保留该区别。
- 目录缺失、工具未安装/版本变更、历史格式未知、SSH 断开、容器重启等均独立报错。已存在工作的标签、会话文件和进程不自动关闭、不清理。
- 不在原有工作区恢复时顺带启动所有 Agent；批量恢复、会话归档删除、跨设备同步不进首版。

## 7. 实施顺序与验收

1. 先完成 Docker 附件功能既有验收；当前处理链测试通过，前台 GUI 锁屏阻塞不应被设计工作掩盖。
2. 标签导航：复用动作、添加默认组合和提示，补 keyDown/keyUp/连发、kitty 增强协议、嵌套 tmux、弹窗及文本框回归。
3. Agent 会话基础：本机和明确 SSH 目标、三工具能力探测、最近记录/原生选择器、项目目录新终端、按 ID 恢复到新标签；工具格式支持由独立测试锁定。
4. 运行中定位和已确认 Docker 目标：先优先复用 Farport 已管理实例，再扩大外部 tmux 发现；不按名称猜容器、会话或用户。

核心验收：

- 导航后实际 PTY 接收字节为零（含按下/释放/连发），新旧标签内部 tmux 的窗口/分栏和前台输入均不变；各键盘布局的辅助 flags 不造成误判。
- 当前 Agent 正在运行时点击历史恢复，新开标签而不向原终端注入一个字节；运行中已定位项直接切回，不产生第二个进程。
- 同 ID/同路径在不同主机、用户、容器的记录不能串台；目录切换和恢复进程实际 cwd 必须匹配目标，不只看 `PWD` 环境变量。
- 恢复指定会话后的原生 ID 与历史一致；不存在的历史明确失败，不得显示成功或悄悄新建。
- 中英文、权限不足、未知版本、过大/损坏/被并发写入的索引、危险标题/路径、断线、容器更换、密钥/内容隐私边界均测试。

## 8. 待确认的产品默认值

推荐直接采用：新增 Command+Option 组合但保留旧键；当前设备全部项目、当前目录优先；恢复默认新标签；已运行会话优先切回；只读索引、不读正文；设备/容器不明确就不执行。

其中“只读索引、不读正文”是严格默认目标，不是三工具 SDK 都能保证的现状：不满足该默认的工具使用原生选择器兜底，开启目标侧 SDK 历史扫描需单独说明权限与副作用。

尚未获得统一确认的分支：是否把常用恢复会话默认放入 tmux；是否提供全设备汇总；是否需要会话正文搜索。建议首版分别为“遵循当前终端偏好”“不做”“不做”。不要为了这些非首版能力延迟高频流程。
