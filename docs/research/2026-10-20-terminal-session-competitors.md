# 终端 Tab 与 Agent 会话入口：三个竞品的有边界研究

核验日期：2026-10-20（北京时间）。对象：iTerm2、Ghostty、Zellij；仅核验官方资料，未安装竞品或执行交互验收，不声称对应某个最新发行版。

## 范围与取舍

- 只回答两个设计问题：应用终端 Tab 怎样避免抢占 tmux 输入；怎样组织当前设备上的 Claude Code、Codex、Pi 的发现、启动、工作目录与恢复入口。
- **不研究三种 Agent 的命令、会话存储格式或扫描实现**，不读取实际用户会话正文、凭据或真实配置。本次也不检查 Farport 功能实现，因此下文全部“借鉴”都是建议，不是产品现状。
- 已检查仓库根目录、`docs/`、`docs/research/` 的 `AGENTS.md`，未发现额外约束文件；遵循本次提供的操作手册与单文件、无提交边界。
- 已参考 `2026-10-19-additional-terminal-products.md` 的 Wave 目录打开终端、命名工作区与恢复入口研究，以及 `2026-10-19-竞品调研与产品优先级.md`。**本轮不再选 Wave**，避免重复工作区泛调研；用 Zellij 补足“恢复究竟恢复什么”的反例。
- 证据标记 `[I*]`、`[G*]`、`[Z*]` 对应文末确切官方 URL；“不能证明”是证据边界，“建议”是产品判断，均不冒充官方承诺。

## 1. iTerm2：区分切换既有 Tab、新开终端与选择工作目录

**官方已验证事实：**设置页明确，Tab 通常用 `⌘+数字` 选择，修饰键可更改；窗口与分屏另有选择设置。[I1] Profile 的快捷键默认新开 Tab，按住 Option 则新开窗口；Initial Directory 可指定起始目录，或沿用当前 session 的目录，但后者明确限于新建 Tab。[I2] Open Quickly（`⌘⇧O`）可按 Tab 标题、命令名、主机、Profile、目录等查找 session，也能新建 Tab。[I3] **不能证明什么：**Profile 是启动配置，不是 Agent 的历史 session；这些页面不能证明 Open Quickly 能发现任意终端外的进程或枚举三种 Agent 的历史记录，也不能证明指定起始目录就恢复了 Agent 上下文。远端目录也不能想当然：Profile 页面明确远端 PWD 展示需要 Shell Integration。[I2] **适合 Farport 借鉴什么：**用应用层修饰键承担 Tab 导航；会话搜索结果同时显示设备与目录，明确区分“定位已打开终端”“在此目录新开终端”“恢复 Agent 会话”。借鉴可搜索的入口，而不是照搬 Profile 配置中心或假定 iTerm2 已实现跨 Agent 发现。

## 2. Ghostty：明确快捷键作用域与是否把按键送给终端

**官方已验证事实：**Ghostty 提供上一 Tab、下一 Tab、按序号选择 Tab 的动作；序号超出范围时选择最后一个 Tab。[G2] 默认绑定会消费按键，不把对应编码交给终端内程序；`unconsumed:` 则仍发送编码，`performable:` 仅在动作可执行时消费，`global:` / `all:` 不受这两种透传条件控制。[G1] 快速终端隐藏后再显示会保留原窗口状态，但官方明确其不随应用重启恢复；它常与全局快捷键搭配，不是应用内 Tab 切换。[G2] **不能证明什么：**存在可配置绑定不等于自动识别所有 tmux 自定义前缀；“不消费”反而可能让应用动作和终端动作同时触发，不能被包装成防冲突方案。快速终端的显示/隐藏也不证明进程持久化或 Agent session 恢复。**适合 Farport 借鉴什么：**首期仅定义应用内 Tab 动作与确定的输入消费规则，不引入全局快速终端。先查应用内部快捷键重复，再验证 tmux 输入原样送达；不能把“检测到 tmux 时全部透传”或照搬 `performable:` 当作无冲突保证。

## 3. Zellij：把存活会话与“按记录重新创建”分开

**官方已验证事实：**Zellij 默认把 session 序列化到缓存，退出或崩溃后的记录可在 session-manager 的 `EXITED` 区选择恢复；默认保存布局及各 pane 的运行命令，恢复时重新运行这些命令，视口与滚屏需另外配置。恢复的命令先停在 “Press ENTER to run...” 提示后，避免未经确认重跑。官方还说明：遇到包装命令等情况，运行命令的发现可能不准确。[Z1] **不能证明什么：**由“重新运行命令”可知，这不是原进程内存继续执行；即使布局和输出回来，也不能据此宣称 Agent 的会话身份、对话上下文或任务进度已恢复。命令发现不准确的已知边界更不能用来推导可靠的跨 Agent 识别。**适合 Farport 借鉴什么：**分开呈现“可定位的已打开终端”和“候选恢复记录”，恢复前展示设备、Agent、目录及会话标识，并由用户明确触发。借鉴状态分组与执行确认，不复制历史命令重放、滚屏存档或跨进程恢复系统；缺少原会话时不能悄悄启动新会话并称为恢复成功。

## 收敛到 Farport 的两个最小设计建议

以下是原型建议，尚未验证 Farport 现有快捷键、系统冲突或 Agent 实际恢复能力；不新增第三条产品线。

### A. 应用终端 Tab 导航，不占用 tmux 前缀

- **候选键位：**`⌘1…⌘9` 定位对应 Tab，`⌘⇧[` / `⌘⇧]` 切换前后 Tab；后两者是本研究的原型建议，不冒称竞品默认值。仅作用于前台应用的终端工作区，先做现有菜单/文本控件冲突检查；不默认注册全局热键，也不采用 Ctrl 字母或 tmux 前缀序列。
- **输入契约：**命中的应用导航键只执行应用动作，不把同一键再次送入 PTY；没有对应 Tab 时保持当前 Tab，不把导航键变成终端输入。这是与 Ghostty 越界选末尾行为不同的明确建议。[G2] 其他终端按键保持原通道，不先拦截再猜测 tmux 状态。
- **能力边界：**这里的“不冲突”指选定键位及测试配置下的输入隔离，不承诺覆盖任意用户键盘映射。需检查 Command 被改映射等情况；设置入口可让用户改绑/取消应用导航键，不尝试自动读取或改写 tmux 配置。

### B. 一个有设备范围的会话入口，三个不同动作

- **先标范围再展示结果：**入口清楚显示当前设备身份；同一路径名不能代替设备身份。可借鉴 Open Quickly 的检索方式，结果只展示必要元数据：Agent 类型、会话标识/可用标题、工作目录、状态及其证据来源。拿不到目录或状态就标“未知”，不通过会话正文生成摘要，不把文件时间等同于运行状态。
- **明确区分动作：**已与 Farport Tab 关联的结果提供“定位终端”；指定目录提供“在此目录新开终端”；候选历史记录提供“恢复此会话”。“启动新会话”是独立入口，不能作为恢复失败的静默回退。仅检测到外部进程不等于能定位或接管其终端。
- **目录不是恢复凭证：**在目录打开终端只满足进入工作目录的需求，不等于恢复 session；不向正在运行的 Agent/TUI 注入 `cd`。恢复所需目录、会话标识、可用性与能力边界由另一个 Agent 的技术调研提供，本研究不规定命令或暗示三种 Agent 支持同一套恢复方式。
- **用户确认才执行：**选中候选记录只展示目标和动作，明确激活恢复后才启动；目录缺失、设备不可达、标识失效分别说明原因，不自动改设备、改目录或重放历史命令。启动成功也不能仅凭“终端出现了”就标成原 session 恢复成功。

## 建议验收，均未执行

| 验收对象 | 最小检查与通过条件 |
| --- | --- |
| Tab 与 tmux 输入隔离 | 普通 shell、tmux、嵌套 tmux、用户自定义前缀分别验证：应用导航只切 Tab；前缀及后续键原样到达终端；无双触发。 |
| 焦点与边界 | 在终端、搜索框、非终端页面及应用失焦状态检查作用域；覆盖只有一个 Tab、目标序号不存在、非美式键盘与现有快捷键重复。 |
| 设备与目录 | 两台设备存在同名路径、目录含空格、目录不存在时，仍能辨认目标；开目录不误称恢复，也不向活动 TUI 发送命令。 |
| 会话状态与执行 | 已打开 Tab、外部运行但不可定位、候选历史记录、状态未知分别展示；选择记录不执行，显式恢复才执行；失败不静默新建。 |
| 恢复判定 | 单独核对原会话标识及 Agent 技术调研定义的成功信号；窗口、布局或旧输出出现均不足以判定 Agent session 恢复。 |
