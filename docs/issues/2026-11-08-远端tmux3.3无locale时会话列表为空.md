# 远端 tmux 3.3 无 locale 时会话列表为空，新建报 duplicate session

- 影响范围：所有远端 tmux 管理功能（会话列表、窗格列表、附件插入前的窗格指纹核对、复制选区等），远端 tmux ≥ 3.3 且非交互 SSH 环境下未设置 `LANG`/`LC_ALL` 的主机。实际触发：my-linux（Ubuntu，tmux 3.3a）
- 发现日期：2026-11-08（用户反馈：这台机器上已有 tmux 会话，Farport 显示“暂时无法读取 tmux”，新建会话 `work` 提示 `duplicate session: work`）
- 修复 commit：待提交
- 严重程度：高（该类主机的 tmux 页面完全不可用）

## 现象

tmux 页面持久会话、终端窗格、已附着客户端都是 0；空状态显示“暂时无法读取 tmux”；点“新建会话”报 `duplicate session: work`。

## 定位过程

1. 新建报 duplicate，说明 tmux 可执行、服务端在运行、`work` 已存在。问题出在列表的读取或解析上，而不是 tmux 缺失。
2. 从 Mac 用 ssh 在 my-linux 执行 `tmux list-sessions -F`，能列出 `my-linux`、`work` 两个会话。远端 `LANG`、`LC_ALL` 均为空，tmux 版本为 3.3a。
3. 第一次测试的格式串写的是字面 `\t`，看不出问题。改成和 App 一样传入真实 Tab 后，用 `od -c` 查看输出，发现 Tab 被替换成了 `_`：`$0_my-linux_1794124726`。
4. 对比测试：
   - 不加参数：Tab 变成 `_`；
   - `tmux -u`：Tab 保留；
   - `LC_ALL=C.UTF-8`：Tab 保留。

## 根因

tmux 3.3 起，如果客户端判断终端不支持 UTF-8（无 locale 时即如此），会把命令输出中的控制字符替换成 `_`。Farport 的 `TmuxService.sessions()` 按 Tab 拆分字段，并要求正好 5 列；不满足的行会被 `compactMap` 静默丢弃，所以列表为空。会话实际存在，因此新建时报重名。

同一前缀还用于 `panes()`、`attachmentTarget`、`pasteValidated` 的窗格指纹比较等，这些都依赖 Tab 分隔，同样会受影响。

## 修复

`Sources/OpenSSHBackend/TmuxService.swift` 的 `prefix` 统一加上 `-u`：

```diff
-        get throws { (host == nil ? ... : RemoteTmuxCommand.executableReference) + (socketName.map { " -L " + RemotePath.quote($0) } ?? "") }
+        get throws { (host == nil ? ... : RemoteTmuxCommand.executableReference) + " -u" + (socketName.map { " -L " + RemotePath.quote($0) } ?? "") }
```

`-u` 是早期版本就提供的全局选项，只声明客户端支持 UTF-8，不修改远端配置，也不影响已运行的服务端。附带好处是中文会话名也能原样输出。

## 验证

- 在 my-linux 上手动对比 `tmux` 与 `tmux -u` 的 `list-sessions -F` 输出（`od -c`），确认加 `-u` 后 Tab 被保留。
- `swift build --build-system native` 编译通过。

## 避免再犯

- 解析 tmux `-F` 输出时，必须考虑远端非交互 SSH 没有 locale 的情况。测试格式串时要用真实控制字符，并通过 `od -c` 检查，不要用字面 `\t` 判断。
- 所有 tmux 命令都应通过 `TmuxService.prefix` 拼接，不要另写 tmux 调用。
