# 批量移动与目录刷新竞态

- 发现日期：2026-10-24。
- 严重程度：P2，目录列表可能暂时陈旧；此次回归中未观察到文件内容丢失。
- 影响范围：文件分栏在读取目录时又收到传输完成通知，尤其是多个文件快速完成复制或移动时。
- 修复提交：与本文同一提交，可通过 `git log -- docs/issues/2026-10-24-批量移动与目录刷新竞态.md` 定位。

## 现象与定位

新增剪切移动的界面回归中，中文用例通过，英文用例在等待源分栏显示新测试文件时超时。失败发生在目录内容检查阶段，尚未执行 ⌘X，并不是英文快捷键分发问题。

此前复制完成会触发一次目录读取。若随后新增文件并调用 `load()`，相同目录仍处于读取状态时，重复请求会被忽略。传输完成回调也仅在 `!model.busy` 时刷新，因此可能没有任何后续请求再次读取最新目录。

## 根因

防止重复导航的规则被用于需要最终一致性的文件变更刷新。忽略重复导航可以避免重启慢速读取，但直接丢弃变更刷新，会使旧的目录读取结果成为最终界面状态。

## 修复

- 保留 `load()` 对重复导航的抑制，不破坏大目录读取及导航取消逻辑。
- 增加 `refreshAfterTransfer()`：忙碌时合并记录待刷新请求，当前操作结束后再读取一次。
- 待刷新请求绑定导航取消标记；关闭分栏时清除请求，不在已关闭分栏上重启读取。
- 移动完成、失败或暂停时刷新两侧列表，反映已实际落地的文件变化。
- 确定性回归模拟忙碌时收到连续刷新请求，验证任务结束后读到新增文件；另验证停止分栏会取消待刷新。

## 移动安全边界

- 剪切只记录来源，粘贴才创建移动任务；成功入队后消费剪切引用，避免重复粘贴。
- 完整连接配置一致才采用同机优化；不凭相同 IP 合并不同 SSH 端口或用户。无法确认是同机时走跨端点传输。
- 同机复制使用系统 `cp` 写入私有 `.swb-<任务ID>.copy/payload`，拒绝不安全暂存目录或符号链接，再沿用覆盖确认与安全落位机制。暂停后重做当前未完成文件；已有流式 `.part` 断点仍使用原路径校验续传。同机无目录合并的移动使用系统 `mv` 将条目放入私有 `.swb-<任务ID>.move/payload`，再安全落位；跨文件系统的实际搬运由系统 `mv` 负责。
- 已存在目录的合并沿用逐项冲突确认；同机文件复制仍使用 `cp`，校验完成后逐项删源。
- 跨端点移动逐文件比对内容，删除前复查；只删除清单内已核对的文件，目录使用非递归 `rmdir`。新增条目、内容不一致或权限失败会停止后续删源。
- 已经移动的部分不会自动撤销。停止移动保留原任务及暂存位置，必须从该任务继续；不要在过程中编辑两端或手动删除暂存目录。
- 不支持 POSIX Shell 的端点保留 SFTP 路径；此次未新增 Windows 实机验收，不将其列为实测通过。

## 验证方式

```sh
bash scripts/check-file-moves.sh --ssh
bash scripts/check-file-moves.sh --ui
bash scripts/check-file-panes.sh --ssh
.build/debug/workbench-tests
```

检查范围包含本机原生 `cp` / `mv`、移动前后 inode、目录与隐藏文件、冲突确认、暂存恢复、部分删源后恢复、目标同长度损坏、源新增条目，以及隔离 SSH 双主机和 Mac 双向移动。界面回归实际投递 ⌘X / ⌘V，检查多选移动、两侧刷新、重复粘贴和文本框剪切隔离。

完整分栏回归还曾在进入剪切阶段之前的表头排序检查超时；这是独立的原有回归点，未在本次修改排序实现。完整分栏通过记录与该次失败记录分别保留，新增 `--ui` 专项不依赖排序测试，不将专项成功当作全部分栏回归均通过。
