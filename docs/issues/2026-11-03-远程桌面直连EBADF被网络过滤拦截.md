# 远程桌面直连报 EBADF：本机网络内容过滤丢弃连接

- 影响范围：远程桌面第 1 期预览（`1b905eb`）；装有企业安全软件（网络内容过滤扩展）的 Mac 上，以“可信局域网 / VPN 直连”连局域网内的 VNC/屏幕共享
- 发现日期：2026-11-03（用户直连 mac-mini 时报错）
- 修复 commit：待提交
- 严重程度：中（直连不可用；经 SSH 不受影响）

## 现象

直连 mac-mini（同一 /20 子网）的 5900 端口，连接立即失败，报错 `网络错误：Bad file descriptor`。在 mac-mini 本机直连同一端口正常；同一台办公电脑上经 SSH 连接正常。

## 定位过程

1. 上一轮在 mac-mini 本机隔离测试：握手、认证方式、登录框均正常；排查了应用内所有显式关闭描述符的代码，没有发现问题，于是加了协议阶段日志。
2. 在出错的办公电脑上，用系统自带的 `nc` 连 mac-mini 的 5900 和 22 端口，同样报 `connectx ... Bad file descriptor`；`ssh`、`curl` 和 Python 连同一地址都能成功。由此判断问题和 Farport 代码无关，而是系统层按进程拦截。
3. 用自编译的 C 探针复现时，探针被云壳当作未报备软件直接杀掉（退出码 137），这条路走不通。
4. `log show` 查内核日志，找到决定性证据：

```
cfil_inp_log <CFIL: RECEIVED CFM_OP_DROP>: [49101 SSHWorkbench] <TCP out ...> lport 55046 fport 5900 laddr 30.164.201.151 faddr 30.164.195.163
cfil_inp_log <CFIL: flow_divert option is NOT set: DROP - DETACH>: [49101 SSHWorkbench] ...
```

近 8 小时内，SSHWorkbench 连 `30.164.195.163:5900` 共有 10 次被丢弃；首次连接还出现过 `tcp drop ... reason: NECP`（错误 65）。

## 根因

本机装有网络内容过滤系统扩展（`systemextensionsctl` 可见 `com.alibaba.endpoint.aliedr.ne` 和 Symantec 扩展；具体是哪一个下发的裁决，日志里没有直接标明）。它在 SYN 发出时对 ad-hoc 签名的 Farport 和 `nc` 下发 DROP，并拆掉套接字，`connect()` 因此当场返回 EBADF；系统 `ssh`、`curl` 等进程则被放行。正式版 `/Applications/Farport.app` 同样是 ad-hoc 签名，预计也会被拦截（未单独实测）。

这是企业安全策略，Farport 不应、也不会尝试绕过。

## 修复

`RFBStream.connect`：`connect()` 返回 EBADF 时，报错改为“连接被本机网络过滤拦截（常见于企业安全软件），请改用经 SSH 连接”，不再显示难以理解的 “Bad file descriptor”。

## 验证

- 核心 2848 项断言通过；Release 预览包编译通过。
- 界面上直连的报错文案：待在办公电脑上实测确认。

## 避免再犯

- 网络类“怪异 errno”（EBADF、EPERM）先查内核 CFIL/NECP 日志：`log show --predicate 'process == "kernel" AND eventMessage CONTAINS "CFM_OP_DROP"'`。
- 用系统自带工具（nc、curl、ssh）在同一台机器上做对照，比在另一台机器上复现更快。
- 办公电脑上不要编译临时二进制做探针，会被安全软件拦截；直接用已打包的应用测试。
