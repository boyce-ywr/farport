# 标签实际拖拽与紧凑工作区

- 日期：2026-10-14；版本：0.1.6；严重程度：中（标签排序入口不可用、目录链接无法进入）。
- 修复提交：见本文件首次引入的 Git 历史。

## 现象与根因

0.1.5 的标签验证仅调用排序数据处理函数，没有走鼠标按下、拖动、释放。实际标签由 SwiftUI Button 和外层 onDrag 组合，鼠标拖动未触发排序。新的 `compact-workspace` 原生事件测试在旧实现稳定失败，说明“函数正确”不能证明拖拽入口可用。

同时，文件来源条把每个会话映射回终端分组 ID；即使触发拖放，移动一个分栏的文件来源也会移动整个终端分组，不符合独立来源排序语义。原生 NSView 背景探测的边界也不能当作按钮精确边界：本环境中多个代表视图覆盖整条滚动内容，必须使用 SwiftUI 实际布局矩形定位目标。

符号链接的列表类型来自 LSTAT。预览虽然对目标做 STAT，但把所有“不是普通文件”的目标误报为特殊设备，包括正常的目录链接；双击也仅识别原始目录标志，因此 Termux storage/shared 无法进入。

## 修复

- 同窗口标签使用独立的鼠标跟踪区域，按实际按钮矩形判断按下、拖动阈值和释放目标。点击释放保持普通选择，关闭按钮不在拖动区；Esc 取消，跨窗口/页面变更不转移会话。拖动目标高亮，并在滚动条边缘辅助滚动。
- 终端组排序只改变 TerminalLayout.tabs；文件来源有独立的会话顺序，来源选择、缓存目录、终端布局和连接身份不变。
- 去除独立的大标题主机信息行，把工作区切换、主机菜单、附件和搜索入口合并为一行工具栏。搜索默认折叠，侧栏可完整折叠并记住用户偏好。已发送附件用单行提示代替大横条；失败/未完成的操作提示保留。
- 目录链接先只读检查目标类型，预览提供“打开链接目标文件夹”，双击解析目标目录并加载。普通文件链接可只读预览，但仍禁止通过链接编辑；传输扫描、递归删除、HTTP 目录隔离规则不放宽。
- Markdown 使用 Foundation 解析和原生富文本展示标题、强调、列表、引用、代码与基础表格。原始 HTML 不执行，图片不自动加载；仅 HTTP(S) 链接可在确认后外部打开。编辑器可并排实时预览，保留旧内容/属性校验及原子保存规则，512 KiB 编辑上限不变。

## 验证

- 原生事件回归：终端标签六次向前/向后拖动、文件来源独立拖动、侧栏按钮折叠、搜索展开/关闭。1360×860 内容尺寸下，折叠侧栏后的终端原生视图为 1352×683；连接 ID 保持不变。
- 补充验证同一分组内的分栏会话可单独调整文件来源顺序，不改变分组布局。
- 本机与隔离 SSH 均验证目录链接预览/打开、普通文件链接只读、失效链接提示及 Markdown 保存回读、旧版本保存冲突拒绝。
- 用户指定 Termux 设备只读验证：shared 符号链接实际打开到 `/storage/emulated/0`，不修改或重命名任何远端文件。测试地址/用户和截图仅留在忽略的 `.test/` 中。
- Markdown 预览及编辑器并排截图已查看；测试中活动 sheet 阻止 QA 退出时，先关闭测试 sheet 再退出，不终止用户窗口。
- 新打包默认产生 Universal、arm64、x86_64 三种独立应用和 DMG/ZIP。升级仍优先原生架构；通用包不是额外平台或 Intel 真机运行的证明。

## 边界

原生合成鼠标事件不等于实体触控板全场景测试；多屏长期使用仍需人工覆盖。文件来源顺序在当前窗口内独立保留，不增加跨启动终端会话恢复功能。Markdown 不实现完整网页或远端资源自动代理。
