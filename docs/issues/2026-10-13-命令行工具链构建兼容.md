# 命令行工具链构建兼容

- 发现日期：2026-10-13。
- 影响：仅安装 Command Line Tools、使用本机 Swift 6.4 / macOS 27 SDK 构建时，默认构建路径不能完成应用编译。
- 严重程度：开发阻塞，不涉及用户数据。
- 修复 commit：未提交。

## 现象与定位

1. `swift test` 默认选择 Swift Build，引入 Metal 编译步骤，但当前工具链没有 `metal` 可执行文件；同时不存在 XCTest 框架。
2. 切换 `--build-system native` 后，SwiftTerm 的着色器作为资源打包，核心模块能成功构建。
3. UI 构建继续报 `SwiftUIMacros.StateMacro` 不存在。读取实际 SDK 接口发现：SDK 同时定义了传统 `State<Value>` 属性包装器和同名 `State()` 宏；CLT 没有提供 SwiftUI 宏插件。
4. 最小复现证明：显式写 `@SwiftUI.State<Int>` 仍命中宏；通过类型别名指向传统属性包装器则通过类型检查。

## 修复

- 构建脚本显式选择 native 构建引擎，不修改系统 SDK，也不修改 SwiftTerm 源码。
- `ViewState<Value>` 仅为 `SwiftUI.State<Value>` 的类型别名，仍使用系统属性包装器，不是自实现状态系统。
- 使用 Foundation 检查可执行文件组织核心断言和集成测试，不依赖当前环境不存在的 XCTest。
- SwiftTerm 资源包随应用一并分发，不能依赖开发机 `.build` 目录。

## 验证与后续

- 原先失败的 UI 构建已通过；核心断言与真实 SSH 集成检查均有独立非零退出码。
- native 引擎在当前工具链中标记为 deprecated。完整 Xcode 工具链可在后续验证通过后迁移默认引擎，不能提前假设兼容。
- 保留最低 macOS 14 部署目标。当前系统运行验证不等于已在 macOS 14 真机上验证。
