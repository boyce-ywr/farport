# 连接复用与主机绑定

- 日期：2026-10-13。
- 影响：开发版本中编辑已有主机的端口/地址后，后续请求可能复用原来的主机连接。
- 严重程度：高；可能使用户在错误的主机上操作。
- 修复 commit：未提交。
- 发现范围：仅隔离测试节点，未连接生产主机。

## 可重复的失败信号

集成检查先建立节点 A 的持久 SSH 通道，再保留相同 profile UUID、把端口改为节点 B，执行 `hostname`。修复前返回了 A，测试以“修改端口后仍连接到了旧主机”失败。

## 根因

ControlPath 只包含 profile UUID。SSH 复用已存在的 socket 时并不重新以新端口建立连接。界面层也需要区分保存的主机配置与已经建立连接的快照，不能只把顶栏切到另一个主机、却仍展示之前的终端。

## 修复

- socket 名包含连接参数摘要，并使用 OpenSSH `%C` 区分实际解析后的连接目标；保持 Unix socket 路径足够短。
- 凭据查找账户也包含连接参数摘要，避免编辑地址/端口后直接复用另一连接范围的保存凭据。
- 未完成传输引用的主机不能修改连接参数，必须先完成或取消任务。
- 切换主机/工作区时选择该主机的终端；点击终端标签同步主机选择。
- 终端顶栏显示该已建立连接的配置快照；编辑主机后文件和 tmux 模型重新创建。

## 回归

保留跨端口、同 UUID 的真实双节点检查。它比较远端实际 `hostname`，不是只验证拼出的参数字符串。界面切换仍需在应用获许运行后做实际图形验收。

## 回归过程发现的 socket 长度限制

首轮增加连接摘要后，基础连接立即失败。直接运行等价 OpenSSH 参数取得明确错误：`unix_listener: path ... too long for Unix domain socket`。macOS 上不仅要计算 `%C` 展开后的路径长度，还要为 OpenSSH 创建 listener 时追加的随机后缀预留空间。

修复为短应用目录摘要、包含完整 profile UUID 与连接参数的摘要前缀，加 OpenSSH `%C`。摘要不包含密钥内容。此路径在当前用户下展开后约 75 字节，连同随机后缀仍低于 Unix socket 上限；仍由原有双节点真实连接检查覆盖，而不只测试字符串长度。
