# 预览服务并发关闭导致闪退

- 发现日期：2026-10-16；此前 2026-10-15 的报告已有相同故障签名。
- 严重程度：高，可能使应用退出并断开普通 SSH 会话。
- 受影响版本：0.1.8（9）及修复前的预览服务实现；修复构建：0.1.8（11）。
- 修复提交：见本文件首次引入的 Git 历史。

## 现象与复现

两个用户报告均为 `EXC_BREAKPOINT / SIGTRAP`，故障线程在 `FilePreviewServer.deinit` 释放信号量时触发 libdispatch 的 `Semaphore object deallocated while in use` 检查。主线程的 SwiftUI 布局栈不是本次崩溃位置，也不是此前发行包启动时的 SIGKILL 问题。

回归使用真实本机 HTTP 套接字，让四个媒体 Range 请求返回响应头并保持传输，再停止和释放预览服务。旧代码第一轮即以信号 5 退出；生成的崩溃报告同样包含上述 libdispatch 错误和 `FilePreviewServer.deinit`，不是根据截图猜测。

## 根因与关联风险

原实现用初值 4 的信号量限制连接：接入时 `wait`，取消回调从连接表移除成功后才 `signal`。`stop()` 提前清空连接表，迟到的回调无法再归还计数；如果对象先被释放，回调的弱引用也无法完成归还。最终信号量销毁时计数低于初值，触发系统断言。

同路径还有以下风险：接入检查和登记之间可插入 `stop()`；超时闭包强引用连接 120 秒；浏览器断连没有单独取消正在进行的远端读取；取消发送需要等固定长超时，且发送错误被忽略。

## 修复

- 删除限流信号量。接入、登记、停止和槽位释放统一在同一把锁下判断，以请求表限制最多四个槽位。
- 已进入文件读取的请求，保留槽位直到工作退出；不能因为浏览器先断开就启动无界后台读取。
- 每个请求拥有取消标记，断连、失败、超时或服务停止均能取消对应 SFTP 读取和发送等待。
- 发送完成显式检查错误，每 100 毫秒检查取消；取消后不再尝试写入第二份 HTTP 错误响应。
- 超时闭包使用弱引用，连接回调不再依靠父对象释放信号量。重复停止安全；停止后的新连接被拒绝，晚到的 worker 不会恢复服务。
- listener 失败会停止服务并终止初始化，不返回看似可用的服务。

没有通过额外 `signal()`、无限保留服务对象或延后析构来掩盖问题。

## 同类代码审计

检查了 `FilePreviewServer`、`ProcessRunner`、`SFTPClient` 和更新下载器使用的信号量/DispatchGroup：预览连接限流是生产代码里唯一初值大于零的信号量。其余完成通知初值为零，回调持有通知对象；管道读任务的 `enter/leave` 使用同一被闭包持有的组并在 `defer` 中配对。未发现相同的“清空索引后漏归还”模式，因此不对无证据的代码作无关重写。

## 验证

- `workbench-tests --preview-lifecycle-check`：50 轮四路媒体传输中关闭、20 轮半包请求析构、20 轮异常请求后恢复、30 轮并发接入/停止竞态；验证第五路被拒绝、停止后释放和 URL 撤销。
- `workbench-tests --preview-lifecycle-ssh .test/app`：10 轮隔离 SSH 的四路媒体读取，覆盖客户端先断开及服务器先停止，校验后台读取与服务在 4 秒内释放。
- `workbench-tests --preview-timeout-check`：真实 120 秒请求超时，计入调度容差后检查四个连接关闭，随后新请求成功。无需缩短生产超时来通过测试。
- GUI `SWB_QA_MEDIA_LIFECYCLE=1`：真实 AVPlayer 在 WAV/MP4 之间切换 20 次，检查加载、播放、暂停、seek、视频解码帧，以及停止后的 URL 无法读取。
- 既有 HTTP 安全检查、Range、HEAD、媒体访问范围和核心测试继续通过。生命周期短回归已接入核心测试；完整入口为 `bash scripts/check-preview-lifecycle.sh --ssh`。

原始崩溃报告、日志及截图留在 `.test/` 或本机系统诊断目录，不公开用户标识、主机或报告路径。以上验证覆盖已定位的故障及相关竞态，不承诺所有未知崩溃均不存在。

## 交付验证

构建 11 的 Apple Silicon、Intel、Universal 应用及 DMG/ZIP 已重建。Release 核心程序通过本机和隔离 SSH 的同一生命周期压力测试；安装到本机用户应用目录后，实际 `.app` 通过 20 次 AVPlayer 切换、播放、暂停和 seek 回归。安装版与 Universal 产物的主程序 SHA-256 一致。

直接从构建目录试启动曾被系统以 SIGKILL 终止；随后按正常方式安装并经 LaunchServices 打开成功。没有更改系统防护、签名身份或二进制内容，也没有据此确定 SIGKILL 的唯一根因。它与本次有确定复现和修复的 SIGTRAP 分开记录。

报告来自另一台 Mac 的 `/Applications/Farport.app`，本机安装成功不代表那台机器已经升级；该机器仍需安装构建 11。旧构建 9 不含此修复。
