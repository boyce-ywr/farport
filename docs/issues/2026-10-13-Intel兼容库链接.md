# Intel 兼容库链接

- 日期：2026-10-13。
- 影响：x86_64 发行构建。
- 严重程度：构建阻塞。
- 修复 commit：未提交。

## 现象

本机 CLT 的 `libswiftCompatibility56.a` 等兼容库只有 arm64 / arm64e 切片。SwiftTerm 的较低部署目标触发旧版 runtime 兼容库链接，Intel 主程序出现 `__swift_FORCE_LOAD_$_swiftCompatibility56` 未定义符号。

## 定位与处理

通过 `lipo -info` 核实兼容库确实缺少 x86_64，再通过 `nm -u` 确认引用来自 SwiftTerm 对象。应用本身最低部署版本是 macOS 14，不提供 SwiftTerm 上游较低 macOS 部署目标的兼容承诺。

发行脚本的 x86_64 构建使用编译器支持的 `-runtime-compatibility-version none`，不携带旧 runtime 兼容层。未忽略 linker 未定义符号，也未引入来源不明的兼容库。重新编译和链接后获得 x86_64 Mach-O 产物。

## 验证边界

该处理验证了当前工具链下的编译、链接和产物架构。Intel / macOS 14 的实际运行尚未完成，需要专门验收；如果未来降低最低系统版本，必须重新评估该构建选项，不能直接沿用。
