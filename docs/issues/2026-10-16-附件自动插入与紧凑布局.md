# 附件自动插入与紧凑布局

- 日期：2026-10-16；版本：0.1.8（10）。
- 严重程度：中。影响附件连续操作以及传输、监控页面的信息密度。
- 修复提交：见本文件首次引入的 Git 历史。

## 附件根因

原实现把终端所有输出到远端的数据都记作“用户输入”。光标位置查询、设备属性查询等协议的自动回复也经过这个回调。复现中仅向终端输入三条查询，就触发三次输入计数；上传完成后，输入版本与上传前不同，因此安全检查拒绝自动插入。

另外，重复选择同一个窗格会改变焦点计数，附件目标又使用全局当前窗口而不是所属终端窗口，导致没有真正换目标也可能被拦截。

## 修复与安全边界

- 在 SwiftTerm 的协议回复入口直接发送协议数据，不计为用户输入；真实文本输入、粘贴和鼠标目标操作仍计数，不按字节内容猜测。
- 焦点版本统一跟随实际工作区/终端变化；重复选择同一窗格不改变版本，切走再返回仍留下变化记录。
- 上传绑定终端所属窗口。自动插入时必须是当前活动应用、前台原窗口、原会话及连接，且没有新的用户输入；切换目标、重连和后台状态仍阻止自动插入。
- 全局和主机级手动策略不被覆盖。普通文本直接粘贴，多行文本保留确认；图片和文件先上传校验，再插入路径，永不自动回车。
- Cmd+V、右键粘贴、Finder 文件拖入共用同一流程；tmux 继续校验窗格及前台进程身份。

## 布局与 Finder

- 完成传输去掉整条占位进度条，名称、来源、大小、状态与操作对齐；失败信息、暂停/继续及详情保留。
- 下载完成后可在 Finder 定位目标，上传可定位本机源文件。远端互传不显示本机定位入口；文件被移动/删除时提示，不改为打开无关目录。
- 磁盘列表改为挂载点、已用/总量、可用、使用率的 32 点高表格行。系统信息分为操作系统、硬件、当前用户；窄窗口自动换列，长内容仍能查看和复制。
- 不隐藏虚拟挂载点、不重算硬件指标。本次是布局调整，不改变采集口径。

## 验证

- 修复前自动回包测试失败：三次协议回复被计为输入；修复后为零，真实输入仍增加计数。
- `bash scripts/check-refinements.sh --ssh`：中英文、本机和隔离 Linux SSH，验证 Cmd+V 文本/图片、右键粘贴 Finder 文件、实际拖放回调、自动插入和回读、手动策略、继续输入、切换目标及切走再返回保护。
- 本机和隔离 SSH 的 tmux 自动插入原窗格，等待输入的程序没有收到回车。
- 720/1100 宽度测量：已完成传输行 53 点，四个磁盘行含表头 158 点；系统信息随语言和换行约 362–392 点。已检查深浅色截图；长用户组不会被固定高度截断。
- Finder 定位调用与源/目标路径选择、缺失文件错误均已验证。当前系统未授权自动化读取 Finder 选区及屏幕截图，不能宣称已自动验证 Finder 最终选中状态。
- 公开 README 更新紧凑传输的真实隔离环境截图，并用明确标注的演示数据展示监控布局。私人剪贴板、路径和主机输出只留在 `.test/`。

后续回归应同时测试“协议自动回复”和“真实用户输入”，不能为修复自动插入直接删除所有安全检查。界面验收要结合高度约束和实际截图，不只检查编译通过。
