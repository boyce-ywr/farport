# 文件分栏复制与焦点隔离

- 发现日期：2026-10-20。
- 影响范围：新文件多分栏、本机与 SSH 文件复制、同进程多窗口；不改变终端连接协议。
- 严重程度：中。多栏下焦点或主机身份混淆可能把操作应用到错误视图，必须在发布前回归。
- 修复提交：与本文一起提交，可用 `git log -1 -- Sources/WorkbenchApp/FilePaneWorkspace.swift` 查询实现提交。

## 需求和现象

文件页原来只有一个活动来源，不能并排查看不同主机。复制使用应用内文件数组，跨主机粘贴缺少清晰、可验证的焦点范围。加入分栏后，旧表头监听器仍寻找视图祖先下的第一张表，英文双栏回归出现“目标栏排序改变了源栏”；最大化后又出现隐藏栏截获表头事件。

## 定位与修复

1. 每栏使用独立的 `FilePane` 和按来源缓存的 `FileModel`，复用布局几何但不共用终端布局，防止同主机不同目录互相覆盖。关闭或离开文件栏停止其浏览/预览资源。
2. 键盘监听器绑定自身表格和真实 first responder；路径框、筛选框、弹窗及非活动窗口不触发文件复制。布局完成后重新绑定表格，避免新栏首次显示还没有键盘目标。
3. 表头监听器按锚点落在的表格区域匹配，而不是取第一个表格；显式禁用最大化时不可见栏的事件监听。双栏和最大化场景都检查升序、降序、默认三个状态以及另一栏不变。
4. 文件拖拽使用 `TableRow.itemProvider` 提供整行数据；多选行共用一次拖拽快照，避免每行生成不同令牌导致其他行失效。私有令牌只在本进程解析，远端路径不会冒充 Finder 本机 URL。
5. 文件复制绑定系统剪贴板的令牌及 `changeCount`，普通文本复制会使旧文件引用失效。捕获来源时检查浏览模型实际使用的主机连接身份，粘贴/拖入入队前再验证来源与目标，拒绝被删除或改址的主机。
6. `FileTransferTarget` 统一粘贴和拖入的目录检查、主机检查、入队提示。异步 provider 返回后再检查目标是否可用、目录是否仍一致、是否忙碌；混合无效拖入不部分入队。成功接收后消费内部拖拽令牌。
7. 复用 `TransferBatch` / `TransferEngine`：文件夹、多文件、跨主机任务仍保留自复制拒绝、覆盖确认、失败反馈和源文件不删除的规则，不绕过 SSH 指纹验证。
8. 收起预览会取消在途预览、停止媒体及日志跟随，隐藏时单击只选中文件而不继续下载预览；双击普通文件或主动展开预览时再显示内容。

### 尚需人工验证的边界

后续状态：2026-10-20 11:12，构建 15 的新预览包在相同源码下经正常启动完成文件分栏与跨主机回归，早前 `137` 阻塞未再出现。随后构建 16 的正式包仍在隔离升级的启动阶段受阻，包含原路径重试和三次间隔审批尝试，均未输出应用测试日志。预览包成功不能代替正式包成功；完整记录见 `docs/releases/0.1.12.md` 的“正式发布准备”。

构建机的 `CGPreflightPostEventAccess()` 为 `false`，不自动修改辅助功能或安全软件权限。SwiftUI 的拖入接收不直接暴露为祖先 NSView 的注册类型；用伪造 `NSDraggingInfo` 遍历祖先失败只能说明测试方法不适用，不能作为真实拖拽成功或失败的证据。原生拖拽源通过公开的 `NSOutlineView`/`NSTableView` 数据源接口取数据，接收复用生产 `FileTransferTarget`；真实鼠标手势及落点高亮仍需人工验收。

人工验收：打开新预览包，在文件页按 `⌘D`，两栏选择测试主机和空目标目录，拖动一个文件及多选文件到另一栏，检查入队、内容和源文件仍存在；再测试不同应用窗口之间拖拽。不得用原来的 0.1.12 候选包替代本轮包进行验收。

## 防止再犯

- 分栏能力必须同时验证输入焦点、隐藏视图监听、各栏独立状态，不能只测试数据模型。
- 测试实际入队及文件字节，不能把剪贴板提示或 provider 返回成功当作复制完成。
- 分开记录源码回归、安装包启动、真实手势和正式发布；权限受阻时保留边界，不绕过系统安全限制。
