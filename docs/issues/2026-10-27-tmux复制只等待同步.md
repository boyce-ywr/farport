# tmux 复制只等待同步

- 发现日期：2026-10-27。
- 严重程度：P2，用户已选择内容但 ⌘C 不能写入 Mac 剪贴板，反复出现同步提示。
- 影响范围：没有 SwiftTerm 本地选区、而选择由 tmux 或终端程序管理的复制动作。此文没有把所有鼠标捕获场景都归因于同一个缺陷。
- 修复提交：与本文同一提交，可通过本文的 Git 历史定位。

## 现象与复现

用户截图中的提示为“未收到新的终端剪贴板同步；可按 Shift 拖选后 ⌘C 直接复制。”

创建独立 tmux socket 和会话，输出已知中文文本，进入 copy-mode 并选择该行；关闭该隔离服务器的 `set-clipboard`，保留一个无关旧缓冲区。Farport 没有本地选区时向真实终端投递 ⌘C，修复前得到与截图完全一致的提示，Mac 剪贴板没有改变。

## 根因

`SafeTerminalView.copy` 只检查 `getSelection()`。没有本地选区时调用 `TerminalClipboardState.noLocalSelection`，仅等待 800ms 的 OSC 52 回执，不会请求 tmux 复制当前选区。

旧逻辑解决的是“远端先复制或后复制”的提示时序，并没有实现主动复制远端选区。因此，在同步关闭、没有同步或选择尚未触发同步时，等待更久也不能解决。截图本身只能确认进入了这条分支，不能单独证明用户实际 tmux 配置；隔离用例证实了该分支的功能缺口。

## 修复

- 给 Farport 管理的 tmux 终端绑定主动读取入口；本地有选区时仍优先本地复制，不把 ⌘C 转成远端 Ctrl+C。
- 核对 session、pane、进程、copy-mode、选择坐标、矩形模式及版本；通过 `copy-selection-no-clear` 创建带随机前缀的本次复制缓冲，读取原始字节并再次核对选区状态，完成后清理自己的缓冲。
- 保留 tmux 选择和 copy-mode，不取旧全局缓冲，不调用用户的 `copy-command` 或 `copy-pipe` 外部程序，不改 tmux 配置。
- tmux 3.6 及以上显式使用 `-C` 禁止额外的 OSC 52 副作用。旧版本仅在剪贴板同步已关闭时允许独立读取，否则退回本地 Shift 拖选，不临时修改服务器全局选项。
- 主动读取异步执行并受六秒界面超时约束；读取完成前再次检查连接、焦点、复制请求和剪贴板 changeCount。新输入、失焦、连接重置或新复制会作废旧请求；保留原有 UTF-8 和 1 MiB 限制。
- 普通右键复制和顶部菜单对托管 tmux 开放，不再仅因没有本地选区而禁用。真正没有可读选择时，给出明确说明而不谎报成功。

## 验证

```sh
bash scripts/check-tmux-copy.sh --ssh
bash scripts/check.sh
```

专项实际运行本机 tmux 3.8 和隔离 SSH Linux tmux 3.2a，中英文均验证关闭 OSC 52 后复制成功、选区保留、旧缓冲保留、内部缓冲清理、无选区时保持 Mac 剪贴板，以及取消标记。新版本开启同步时显式复制不会触发额外 OSC 52 授权；旧版本不走无法取消副作用的回退。

迟到结果测试覆盖新输入、重置连接权限、窗口失焦、切换活动状态、其他程序更新剪贴板及连续发起新复制；空内容、非法编码和超限内容不覆盖原剪贴板。

2026-10-27 验证结果：新专项中英文本机与隔离 SSH 四组通过；既有中英文 `terminal-clipboard`、`terminal-paste`、`clipboard-policy`、`attachment-auto` 八组回归全部通过；2780 项核心断言和 1069 条英文资源检查通过。原始复现日志为 `/tmp/farport-copy-repro.log`，回归日志为 `/tmp/farport-copy-matrix.log` 和 `/tmp/farport-copy-regression.log`；均仅含测试内容，不包含用户剪贴板文本。

## 保留边界

这次没有发布安装包，也没有替换已安装的应用。普通 Shell 内手动进入的 tmux、嵌套连接以及鼠标松开后已取消的选择，不安全猜测其缓冲归属；仍可用 Shift 拖选后 ⌘C 直接复制。需要保持远端选择才能使用主动选区路径，不宣称所有终端程序自绘选择都已支持。
