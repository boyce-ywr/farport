# Docker 容器附件目标与安全插入

- 日期：2026-10-20。
- 类型：功能缺口及跨执行环境安全边界；严重程度中。
- 范围：Farport 附着的本机 tmux 内直接 `docker exec -it` / 可交互 `docker attach`。远程 Docker、Compose、二次 SSH、容器内切换用户不在首版范围。
- 实现提交：与本文一同提交，用 `git log -1 -- Sources/OpenSSHBackend/DockerAttachments.swift` 定位；不是修改或覆盖已发布的 0.1.12 附件。

## 现象与需求澄清

用户在本机 tmux 里运行容器内 Agent，粘贴图片时出现“窗格可能处于嵌套主机、容器或其他用户环境”的拦截。用户确认自己确实已进入 Docker。原保护没有误报：宿主机临时路径并不保证在容器可见，不能直接删除 `docker` 拦截规则。

目标改为：第一次明确确认容器，按该容器的真实接收用户复制与校验，再向原窗格插入容器路径。已有本机 tmux 主目录缺陷是另一问题，本功能不撤销此前修复。

## 实现与约束

1. 从 tmux pane PID 查询同用户 `proc_bsdinfo.e_tpgid`，再核对前台 Docker 的可执行文件、PID、启动时间和允许的 argv 选项。macOS 直接对非当前控制终端使用 `tcgetpgrp` 返回 ENOTTY，改用内核提供的前台进程组字段；不靠标题、短容器名或终端输出猜测。
2. 只保留 `DOCKER_CONTEXT` / `DOCKER_HOST` / `DOCKER_CONFIG` 等必要选择信息，不输出完整 argv、环境、Docker inspect 对象或认证资料。只接受明确、可识别的本机 Unix socket context；默认 context 文件晚于 Docker 进程启动时拒绝按当前配置猜旧连接。
3. 选择框列出容器身份，但只允许与原进程引用解析为相同完整 ID 的容器。确认前不复制；确认后锁定 daemon ID、endpoint、完整容器 ID、启动时间/重启计数、状态和 UID/GID，不用 root 代替无法识别的用户。
4. 先在限额内形成私有本机快照，再使用 `docker exec -i --user UID:GID` 通过 stdin 写到随机 `/tmp/.farport-attachments-*`。不用默认 root 所有者的文件复制方式，不要求新挂载、重建或修改用户容器配置。每个操作前核对身份与状态。
5. 目录 700、文件 600；不跟随符号链接、不复制特殊文件，校验目录清单、接收用户可读性和 SHA-256。所有路径用 argv 或独立 shell 位置参数传入，包含中文、空格、引号、美元符号、分号的文件名均在夹具中实际验证。
6. 插入前再次验证文件、原窗格、前台 PID/启动时间以及原有连接/输入/焦点条件。使用命名临时 tmux buffer 定向插入，不发送 Enter；切换窗格、复制模式、重进容器、容器重启或内容变化时不误发。原 `TmuxService.target` 对未经确认的 Docker 仍拒绝。
7. 已确认绑定只驻留当前 TerminalSession 内存，同一目标再次粘贴可复用；失效时重新确认。取消选择不会上传，关闭草稿撤销弹窗。清理仅作用于该私有批次，容器身份改变则拒绝跨目标清理，源文件不删除。

## 验证与排查记录

使用本地已有测试镜像、新建两个带专属 label、无网络的容器；只结束本次 tmux 会话和带标签的本次容器，不修改用户运行的容器、进程或配置。

```sh
bash scripts/check-docker-attachments.sh
bash scripts/check-docker-attachments.sh --models
bash scripts/check-docker-attachments.sh --ui
```

- 后端真实路径：前台 Docker 识别、非 root 用户文件/文件夹复制、权限 600/700、哈希读回、取消、超大/链接拒绝、错误容器拒绝、目录内容变化、复制模式、进程变化、容器暂停/重启与批次清理已通过。
- 中英文处理链：准备 → 首次确认 → 上传 → 手动插入 → 绑定复用 → 清理，以及新 Docker 进程重新确认、取消选择都通过；此模式不宣称完成前台键盘验收。
- 早期真实 `⌘V` 检查超时 `active=false`，系统为 `CGSSessionScreenIsLocked=Yes`，未绕过安全策略；用户解锁后中文、英文两轮真实 `⌘V`、原生确认弹窗、默认按钮 Enter、恢复焦点、自动插入和再次粘贴通过，实际容器只收到一次路径且没有自动回车。
- 原生确认测试从内部方法调用加强为向弹窗投递 Return 事件，确保按钮接线也被检查。选择框截图检查中英文布局；截图有透明区域，查看时使用实色背景合成，未把透明底误判为文字缺失。
- 处理链检查曾在打印 PASS 后等待带 sheet 的应用退出；已增加取消/关闭草稿时撤销 sheet、等待弹窗收起，并给脚本进程设置 180 秒上限，不能只看 PASS 字样忽略退出状态。
- 既有核心断言、SSH 集成、普通本机/SSH/tmux 附件、复制粘贴回归与最终预览包检查的结果记录在 `docs/releases/0.1.13-preview.md`；不把开发二进制通过等同于安装包通过。
- 解锁后的收尾结果：2555 项 ARM64 Release 核心断言与 945 条英文资源检查通过；19 组 SSH 集成及中英文原有附件/剪贴板回归通过。0.1.13（17）ARM64 本地预览包经 LaunchServices 完成中英文 Docker 附件检查；隔离 ZIP 副本启动无输出另行记录，不代替正常预览包路径的成功结果，也未绕过组织防护。

## 防止再犯

- “本机终端”与“接收程序位于本机”不同；执行目标必须明确包含容器和用户。
- 不通过放松嵌套环境保护来实现容器附件，不声称能探测容器内所有后续 SSH/su 行为；用户必须确认程序仍位于选定用户/容器。
- 列表发现、用户确认、文件写入、目标复核、终端输入是不同阶段；每个阶段有独立的失败与取消反馈。
- 测试分别证明模型链路、前台按键、文件内容和产物启动，保留失败证据。真实 Agent 是否理解图片仍以 Agent 提示为准，不由路径插入结果代替。
