# tmux 前台程序开启鼠标模式时，右键菜单不显示

- 发现日期：2026-10-15；严重程度：中。
- 影响范围：已开启“tmux 终端右键使用 tmux 菜单”、从 Farport 附着的 tmux 会话。
- 修复提交：见本文件首次引入的 Git 提交。

## 定位

只读检查用户主机发现：tmux 为 3.6，鼠标选项已开启，普通右键和 Meta＋右键绑定均存在；若干前台程序的 `mouse_any_flag=1`。没有修改该主机的配置或发送交互输入。

tmux 的普通 `MouseDown3Pane` 默认绑定会在前台程序接管鼠标时把事件转交给该程序，不保证打开菜单。因此“右键已发到远端”不等于“tmux 菜单已弹出”。

隔离测试用独立会话开启终端鼠标模式、清屏并输出固定标记，确认旧菜单已消失后再右键。修复前等待实际菜单文字超时，复现了相同问题。

## 修复

启用 tmux 菜单时，在原有右键编号映射上加 Meta 修饰，使用 tmux 默认 `M-MouseDown3Pane` 的专用菜单入口。保留原始点击坐标，按下、拖动和松开使用一致修饰。不修改远端全局配置或按键绑定；自定义绑定仍以远端为准。

普通终端菜单、Shift＋右键临时返回普通菜单、鼠标未启用时的确认流程保持原样。手工嵌套 SSH/tmux 的识别边界未扩大。

## 验证与教训

- 本机和隔离 Linux SSH：普通 Shell 与开启鼠标模式的前台程序中，均实际显示 `Horizontal Split` 菜单文字，再用 Escape 关闭，不执行菜单操作。
- 检查其他会话和全局 mouse 值未改变；测试结束清理自身创建的会话。
- 测试不能只检测输入计数增加，也不能误把上一轮残留菜单当作本轮成功。
- 隔离 SSH 的 tmux 3.2a 暴露了测试自身多发一次 Escape 的问题：多余前缀可能与下一次鼠标序列组合。移除重复 Escape，并等待旧菜单消失后，回归通过。
- 用户主机只做了只读配置检查；未打断现有工作会话来自动执行菜单验证。

远端地址、会话原始输出和截图仅保留在 `.test/`，不写入公开记录。
