# 终端复制反馈与进程表头排序

- 日期：2026-10-16；版本：0.1.10（13）。
- 严重程度：中，影响复制可靠性与监控交互。
- 修复提交：见本文件首次引入的 Git 历史。

## 复制问题定位

用户反馈程序显示 `Copied`，但粘贴仍是旧内容。代码确认有两条不同链路：Farport 本地选区直接写入 Mac 剪贴板；tmux/终端程序自己选区后，通过 OSC 52 请求写入。程序可以在请求获准前显示成功，旧实现拒绝后又没有反馈或重新授权入口。截图本身不能证明最终走的是哪条链路。

另一个问题已稳定复现：没有 Farport 本地选区时执行 `copy`，底层仍清空剪贴板并写入空文本。测试先写入标记，执行无选区复制，修复前断言失败。

## 修复

- 本地复制检查有效选区；无选区时不清空原内容，提示 Shift 拖选与 Cmd+C。
- Shift 拖选全过程临时关闭鼠标转发，结束后恢复原设置；即使前台要求捕获 Shift 鼠标也不影响本地选区。不改远端 tmux 配置。
- 有本地选区时优先使用普通右键复制菜单；增加分栏复制、粘贴和权限入口。
- 复制成功反馈以实际 Mac 剪贴板写入和回读一致为准，不依赖远端的 `Copied`。反馈覆盖显示，不改变终端尺寸。
- 远端写入仍先授权；拒绝、后台请求、无效编码、空数据和超限均有反馈。仅在内存暂存最近一条有效待复制文本，最多 1 MiB；用户可显式允许并补复制。重连清除授权和待复制文本。
- 远端读取始终拒绝；本地显式选区复制不要求远端授权，多行粘贴与附件策略不放宽。

## 排序实现

进程表原来只有排序下拉框，表头点击没有处理。原生表头回归首先复现 CPU 点击后顺序未变。新增独立的排序状态与比较器，六列循环升序、降序、默认；数字按原始值比较，缺失值双向均置末，同值按 PID 升序稳定排序。默认恢复 CPU 降序，刷新与筛选保持选择。

文件表已有的表头点击监视器改为接收列标题和索引，与进程表共用。未改文件排序规则；表头边缘仍交给原生列宽调整。

## 验证

- 核心断言覆盖六列、三态、数字顺序、自然名称、空值、零值、无效 CPU、同值稳定性与刷新/筛选。
- 原生 UI：中英文各 36 次点击，覆盖两种宽度、排序箭头、默认箭头清除与新采样顺序；截图检查通过。
- 无选区不清空、中文/emoji 自动换行复制、Shift 拖选且没有远端输入、Cmd+C 和右键写入、粘贴到 NSTextView 内容一致。
- 本机和隔离 SSH：真实 OSC 52 请求拒绝后不覆盖，右键允许补复制后与原生文本框粘贴一致；tmux 输出可经本地选区复制，无需修改其配置。
- 拒绝后不重复弹窗、当前连接授权、后台不覆盖、无效/超限数据及读取拒绝单独验证；不会把模拟权限选择表述成用户真实点击系统弹窗。
- 入口：`bash scripts/check-copy-and-sort.sh --ssh`。测试剪贴板结束后恢复原内容；截图和原始日志保留在忽略目录 `.test/`，不公开私人选中文本。

## 交付边界

Apple Silicon 和 Intel Release 编译、三种 DMG 校验通过。Debug 与独立 Release 程序均通过上述本机/SSH/tmux 复制、Cmd+V 真实输入及表头交互；2109 项核心断言通过。旧文件表的 15 次点击回归通过，没有改变原排序规则。

发行 `.app` 直接执行和附带测试参数启动出现 SIGKILL；静态签名验证正常。原样复制到独立版本目录、正常打开后曾观察到进程，但后续检查已退出，不能将其表述为安装版验收成功。本机没有可用的 Developer ID 签名身份，现有证据也不足以确认终止的唯一原因。未改系统防护、未重签为其他身份，未覆盖或关闭用户当前运行的 0.1.9。

因此 0.1.10 先作为预发布提供，不更新 GitHub 的稳定版指向。附件自动插入的额外回归停在测试窗口未激活（`active=false`）；没有绕过前台保护冒充通过。本次普通文本复制/粘贴有独立的真实 PTY 与原生剪贴板往返结果。
