# 监控刷新时页面上下抖动

- 发现日期：2026-10-15。
- 影响范围：0.1.8 主机监控页，每次开始或结束采集时，状态行下方的分页和内容上下移动。
- 严重程度：中，影响阅读，不影响采集数据。
- 修复提交：与本文同次提交，可通过本文件的 Git 历史查看。

## 定位与根因

状态行在 `busy` 时插入一个小尺寸 `ProgressView`，空闲时将它移除。原生布局回归直接测量这段实际使用的 SwiftUI 视图：宽度为 500 时，空闲行高为 13，加载时为 16。这个 3 点高度差会推移下方整个区域；图标插入也会改变左侧文字的位置。

测试无需 SSH、采集结果变化或动画就能复现，问题在状态行布局，不需要改动采集频率或数据逻辑。

## 修复

把实际状态行提取为 `HostMonitorStatusRow`，供页面和原生布局回归共用。图标所在区域始终保留 16 × 16 的空间，只在采集时创建加载动画。空闲时不显示动画，也不收回空间，文字和下方内容的位置保持稳定。

## 验证

- 修复前，同一回归报错：`空闲 13.0，loading=true 时 16.0`。
- 修复后，中文、英文分别检查首次采集与已有采样时间、500/900 两种宽度，各切换 80 次 loading，行高均保持不变。
- 本机 macOS 真实只读采集、用户/进程/内存数据、暂停与取消检查通过。
- `swift build --build-system native` 与 1530 项核心断言通过。
- Apple Silicon、Intel 的 Release 构建及通用应用签名校验通过；通用应用在当前 Apple Silicon Mac 上通过中文复测，安装后通过英文复测。未进行 Intel 真机运行验收。
- 已更新 `~/Applications/Farport.app`，旧应用备份保留在 `.test/loading-install.*/Previous-Farport.app`；未重启从 `dist/Farport.app` 运行的原有终端进程，也未发布 GitHub Release。
- 原始日志和截图保留在忽略目录 `.test/loading-layout-*`，不公开机器信息。本次未重新验证远端采集逻辑，因为没有改动它。

复测命令（在仓库根目录执行，不需要远端测试主机）：

```bash
swift build --build-system native
workspace=$(mktemp -d "$PWD/.test/loading-layout.XXXXXX")
FARPORT_LANGUAGE=zh-Hans SWB_HOME="$workspace" SWB_QA_SCREEN=local-monitor \
  SWB_QA_OUTPUT="$workspace/monitor.png" SWB_QA_EXIT=1 .build/debug/SSHWorkbench
```

英文复测把 `FARPORT_LANGUAGE` 改为 `en`。这项布局回归也接入已有 `scripts/check-host-monitor.sh` 的监控检查。

## 避免再犯

周期变化的状态图标应保留稳定的布局空间，不能只确认“动画能显示”。回归应测量加载前后的真实布局，同时覆盖首次加载、已有数据和多语言。
