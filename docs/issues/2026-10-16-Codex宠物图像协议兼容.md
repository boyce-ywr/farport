# Codex 宠物图像协议兼容

- 日期：2026-10-16；版本：0.1.9（12）。
- 范围：普通本机、POSIX SSH 终端图像显示；tmux 官方限制说明。
- 修复提交：见本文件首次引入的 Git 历史。

## 定位

用户看到 `Pets unavailable`。锁定的 SwiftTerm 1.20.0 已包含 Kitty/Sixel 解码及绘制，不需要另外安装图像解码程序。Codex CLI 0.163.0 的 `pets/image_protocol.rs` 按终端环境标识选择协议，没有主动查询 Farport 的图像能力；此前 `TERM_PROGRAM=Farport` 不在识别范围。

本机环境断言先复现该差异。官方文档和匹配版本的 Codex 源码同时确认，tmux/Zellij 被显式禁用，不能把图像透传设置当作完整解决方案。

## 实现

- 使用保留品牌的 `Farport-Kitty` 标识表示 Kitty 兼容；不伪装成 Kitty 程序或 iTerm2，也不制造其他终端的窗口 ID。
- 本地登录 Shell 导出该标识；POSIX SSH 检查后在当前连接导出，再 exec 原 Shell。TERM 保持 xterm-256color；Windows/无 POSIX 环境保留默认终端，不修改远端配置。
- 在原生进程输出入口过滤 Kitty APC：处理跨包和多块图像，拒绝宿主文件、临时文件和共享内存传输；限制图像尺寸为 4096×4096、显示行列上限 512、单次累计传输 16 MiB、缓存 64 MiB。保留 ANSI、Unicode、图像删除及 Sixel。
- 同时识别独立的 8 位 APC，避免绕过；不把 UTF-8 的续字节误判成 APC。
- tmux 页增加普通终端入口。保留实际 TMUX/Zellij 信息，不修改 Codex 或用户的透传配置。

## 验证

- 核心回归覆盖环境、登录脚本、PNG/原始内嵌数据、分包、删除、异常参数、超大显示区域、超大传输后恢复、Unicode 和宿主路径阻止。
- 原生图像回归检查实际像素，不仅看协议到达：Kitty PNG、Sixel、40 轮图片替换/删除、备用屏幕进入退出；本机及 SSH PTY 均渲染真实颜色。
- 使用官方 Codex CLI 0.163.0，在隔离 CODEX_HOME 和无模型调用的测试配置中验证内置 Rocky 连续帧及选择器；本机和隔离 Linux SSH 均通过。Linux 包已校验官方 npm 元数据的完整性。
- 真实 tmux 内启动 Codex，确认显示官方禁用说明且不发宠物图像，而非声称 tmux 可用。
- 本机已有自定义宠物是 1536×2288（8×11）图集，当前 CLI 要求 1536×1872（8×9），直接使用会报素材加载失败。这是独立于终端渲染的问题；未改写用户素材，改用 CLI 内置宠物验证。

日志和截图仅放在 `.test/graphics.*`、`.test/pet-research/`；不提交用户配置、密钥、自定义素材或 Codex 二进制。测试入口 `scripts/check-terminal-graphics.sh --ssh`，真实 Codex 需传入独立测试路径变量，缺省不把协议测试冒称为 Codex 实测。

## 交付验收

0.1.9（12）已构建 Apple Silicon、Intel 和 Universal 包。安装到本机用户应用目录后，安装版通过真实 Codex 0.163.0 的本机与 SSH 宠物连续帧、选择器和 tmux 禁用边界检查。回归共通过 2071 项核心断言，本机/SSH 混合分屏和登录 Shell 检查仍通过。原安装版已备份，不会用新版本去重启现存用户终端。

公开说明中的宠物图片来自隔离 SSH 验收截图裁剪，只包含 Codex 选择器及内置宠物，不包含用户路径或凭据。测试使用隔离配置和 `--no-daemon`，未提交模型请求，也没有修改用户的 Codex 配置。
