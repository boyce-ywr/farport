# 文件来源与附件目标绑定

- 日期：2026-10-13，版本 0.1.3。
- 影响：多终端文件浏览与附件粘贴；严重程度：中（操作目标不明确可能导致误操作）。
- 修复 commit：见本文件首次引入的 Git 提交。

## 文件页上下文

旧实现只在终端页面渲染标签，文件页面由当前主机重新构造 FileModel。用户无法看到文件与终端关联，切换主机丢失目录。回归首先复现“文件页没有终端标签”。

改为共用 SessionTabs 和明确的文件来源栏；每个会话/主机有独立缓存，文件来源变化不会改变 TerminalLayout。回归通过真实标签点击验证同主机两个会话的目录、筛选、选择独立，以及本机/另一主机切换、返回后布局不变。不会冒称自动跟踪未提供目录报告的 Shell。

## 附件可达性与竞争条件

远端不能读取 Mac 剪贴板图片的本地临时路径。所有附件入口统一为：捕获来源与目标→选择目标可读目录→唯一私有目录上传→目标机器实际回读并比较 SHA-256→再次检查接收身份→插入路径，不自动回车。

普通终端绑定 session/connection/window/input 世代；tmux 进一步绑定 pane、进程、前台命令、目录和复制/退出状态。对目标变化保留已上传结果并拒绝自动插入。失败不返回附件引用。本机截图暂存仅由明确的剪贴板/拖拽动作创建，生命周期结束清理；不会持续监控剪贴板。

测试证明：权限不足、取消、缺失源文件不返回引用；远端 Python 接收进程在 tmux 中确实读取上传的图片和特殊文件名文件；切换窗格拒绝插入；未手动发送 Enter 前接收程序没有读到完整行。本机 tmux 管理在独立测试 socket 验证，并用应用附着专用本机会话验证关闭标签不结束会话。

## Agent 验收边界

Codex CLI 0.162.1 的真实远端交互界面接受单图片路径粘贴并显示 `[Image #1]`，没有自动提交。另一次远端 tmux 中运行的 Codex 图像请求正确读取了随机图片数字。API 认证只在本机测试中继内存中使用，通过临时 SSH 反向回环通道请求，没有把用户凭据复制到容器。

Claude Code 本机没有已授权环境，未声称通过真实模型验收。嵌套 SSH、容器、换用户和 Agent 权限仍需要用户明确选择实际可访问的目标，不通过更改权限、修改 tmux 配置或伪造附件标记来掩盖不可达问题。
