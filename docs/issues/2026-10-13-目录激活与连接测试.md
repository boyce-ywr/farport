# 目录激活与连接测试

- 发现日期：2026-10-13。
- 影响范围：远程文件表格打开目录；主机配置需要保存后才能验证连接。
- 严重程度：中，阻碍正常浏览和配置反馈。
- 修复 commit：见本文件的 Git 历史。

## 目录点击问题

原实现把双击手势附加在 SwiftUI Table 外层，并读取可能尚未更新的选择状态。原生表格处理鼠标事件，外层手势不能可靠地收到行激活。

回归脚本在真实 SSH 文件表格中向目录行发送鼠标按下/抬起双击事件。修改前返回失败，路径仍停留在远端父目录。

修复使用 Table 的 `contextMenu(forSelectionType:primaryAction:)` 行激活回调，直接采用事件提供的条目 ID，不再依赖旧选中项。根据后续确认的交互要求，目录名称与其他列保持一致：单击仅选中并预览，双击进入目录；移除目录名的单击打开按钮，保留右键菜单与预览区的显式“打开文件夹”操作。导航成功后清空上层目录筛选，避免进入子目录却显示为空。

回归测试直接点击目录名称区域，在第一次鼠标按下/抬起后断言路径未变且目录已选中，第二次点击后断言进入子目录；旧的单击按钮实现会在第一项断言失败。多选复制检查沿用这套点击流程，防止修改破坏 ⌘ / ⇧ 选择。

验证命令：`bash scripts/check-directory-navigation.sh`。此测试运行真实 AppKit/SwiftUI 表格和隔离 SFTP 服务器，不是只调用文件模型。

## 测试连接

主机配置新增测试入口、进行中状态、停止按钮和成功/失败反馈。使用当前未保存的输入；显示名称可留空，但地址、端口等仍校验。测试分为 SSH 认证与 SFTP 访问，后者失败时明确区分，不把仅有 TCP 通路当成连接成功。

使用独立 SSH 连接，不复用现有控制通道，避免更换密钥后得到旧连接的假成功。测试不保存主机、不写远端文件；首次主机指纹、认证和可选钥匙串保存仍遵循现有交互。编辑连接参数或关闭弹窗会取消测试，旧异步结果不会回填新配置。

集成检查覆盖真实 SSH/SFTP 测试、预取消、禁止复用与不改变主机配置文件。

## 弹窗状态一致性

真实弹窗测试进一步发现：分别设置“当前主机”和“显示弹窗”的两个状态时，首次弹窗可能捕获先前的空配置。改为基于主机对象的 `.sheet(item:)`，呈现状态与数据是同一个对象；批量传输弹窗同样用选择快照驱动，避免出现空的传输来源。修复后的弹窗显示真实主机参数及 SSH/SFTP 成功反馈。
