# 本机终端回归：宽字符和活动窗口边界

- 日期：2026-10-13。
- 版本：0.1.2。
- 影响：本机 Shell 的自动化验收，不涉及生产主机。
- 严重程度：低，测试误报。
- 修复 commit：见本文件首次引入的 Git 提交。

## 中文输出断言

本机 PTY、交互模式、登录模式和主目录断言均已通过，完整中文字符串断言仍失败。针对测试输出记录 Unicode 码位发现，每个中文字符后跟一个 U+0000。检查锁定版本 SwiftTerm 的 `getBufferAsData` 实现，确认它默认保留宽字符的占位单元；不是终端显示乱码或 Shell 丢失字符。

回归改用 `BufferLine.translateToString(trimRight:skipNullCellsFollowingWide:)` 获取显示文本，仍要求实际输出整行匹配，并额外验证终端原生搜索能够找到中文。不改写第三方依赖，也不通过删除任意空白掩盖真实内容错误。修正后中文和搜索检查通过，双主题截图人工查看正常。

## 活动窗口与快捷键

后台启动的 QA 进程中 `NSApp.isActive`、`isKeyWindow`、`mainWindow` 均为 false，因此全局菜单没有当前工作区，快捷键命令禁用。单凭这种背景无法断言产品的快捷键失效。尝试替换 SwiftUI 的焦点传递方式没有改变结果，已撤回，以免为了测试修改正常行为。

保留既有菜单/焦点机制。回归分别检查真实菜单的快捷键声明、菜单对应的工作区操作以及操作后真实 PTY 的响应。全局快捷键派发仍需前台交互检查，不能把这些检查宣称为物理按键或输入法的完整验收。

## 防止误判

- 输出标记分段传入 `printf`，避免命令回显自身导致断言假成功。
- 无主机配置运行本机终端，确认没有新增 SSH 控制通道或主机配置。
- 退出、重新打开、多标签、分屏和关闭检查实际子进程状态；混合分屏检查双方输出、配置身份、字体和配色一致性。
- 测试结束关闭本次测试会话，不终止用户已有应用，也不修改 Shell 配置。
