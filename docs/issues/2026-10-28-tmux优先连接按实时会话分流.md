# tmux 优先连接按实时会话数量分流

- 发现日期：2026-10-28。
- 影响范围：启用“连接时优先打开 tmux 工作区”的已配置主机默认连接入口。
- 严重程度：交互行为与用户预期不符，不涉及删除会话或文件。
- 修复 commit：待验证后记录；尚未发布安装包。

## 旧行为与根因

`Workspace.connectPreferred` 先切换至 tmux 管理页，仅在 `lastSession` 非空时查询，并只尝试附着记住的旧会话。首次连接没有记录时不检测；旧记录失效时停留在管理页；多个会话时仍可能直接进入旧会话，缺少创建确认和选择步骤。查询使用 `try?`，失败没有明确反馈。

## 新行为

1. 未启用偏好：维持普通 SSH 终端，不读取 tmux。
2. 启用偏好：异步检测并显示可取消的进度。零个会话显示新建确认和会话名，默认 `work`，取消不写入远端；一个会话直接附着；多个会话必须先选择，列出会话名称、ID、窗口数与客户端数。
3. 新建前复查列表；如果其他客户端已创建会话，改为提示选择，避免按过期列表继续新建。新建命令返回本次会话 ID，仅进入该会话。
4. 选择时复核会话 ID 与创建时间。所选会话消失时重新展示列表，不替换成另一个会话；查询错误单独展示，不当作空列表处理。
5. 页面、主机、配置或请求发生变化时取消旧检测；异步结果在打开终端前再次核对完整连接配置和请求身份。

侧栏双击、顶部默认主机连接菜单及空工作区“打开 SSH 终端”使用同一入口。显式“连接普通终端”、新建普通终端/分屏，以及没有此偏好配置的原生本机 Shell 按钮不改变语义。不会安装 tmux、修改全局配置或结束既有会话。

## 验证

- 独立本机 tmux socket 验证零/单/多会话、非法名称、指定创建、会话消失、取消/失效请求及确认期间出现新会话。
- 隔离 SSH 验证真实检测与附着：空会话提示通过 Esc 取消，Enter 确认创建并附着；唯一会话忽略失效旧记录直接进入；多个会话即使记住旧会话也保持选择，真实鼠标点击列表行再按 Enter 进入指定会话。
- 页面/主机/配置切换、重复请求、检测连接失败与关闭 tmux 偏好覆盖；中英文确认和选择界面截图已检查。
- 2831 项核心断言、1077 条英文资源检查通过；原有本机 tmux 主目录、新窗口与分屏目录继承、中英文本机/隔离 SSH 分屏、浅色/深色本机与 SSH 混合终端回归均通过。原有菜单快捷键声明测试不等于全局快捷键系统派发验收，新会话对话框中的 Esc/Enter 与列表点击则已实际派发。

## 构建与证据边界

常规 SwiftPM 构建仍出现既有 `build planning stopped due to build-tool plugin failures`。本次使用已有 `.test/attachment-perf-20261028/` 独立构建，同一份业务与测试源码、锁定版本的 SwiftTerm 及原生成器产出的元数据；没有修改依赖或绕过失败宣称正式打包通过。未发布或替换已安装应用。

新增 `scripts/check-preferred-tmux.sh`，默认要求先运行 `scripts/test-environment.sh`。脚本只允许带项目夹具标签的本机 SSH 容器，测试会清理其中的 tmux 会话；不要用真实用户主机配置替代。可通过既有 `FARPORT_APP` 指定被测应用。

本地证据：`.test/preferred-tmux-20261028/qa-final.log`、`core.log`、`english.log`、`directory.log`、`split-directory.log`、`local-mixed.log`，中英文截图位于 `.test/preferred-tmux-zh-Hans.*` 和 `.test/preferred-tmux-en.*`。日志和截图仅使用合成数据，不记录真实用户会话内容。

## 避免再犯

“优先 tmux”应由实时状态决定，不把历史记录等同于当前可用会话；有副作用的新建必须有明确确认。默认连接和“普通终端”是不同语义入口，测试必须分别覆盖，并验证取消和迟到结果不能覆盖用户后续操作。
