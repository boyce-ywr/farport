# 附件上传完成时的自动插入焦点竞态

- 发现日期：2026-10-19。
- 严重程度：中，已开启自动插入时偶发退回手动插入。
- 修复 commit：`f1e53ee`；解锁后的验收补充见修改本文的后续提交。
- 状态：实现、核心测试、中英文本机/隔离 SSH/tmux 原生前台回归已通过；不等于新安装包已经交付。

## 现象与分析边界

图片经 `⌘V` 上传成功，却偶尔没有把路径送入原终端。原代码上传后仅检查一次应用、窗口和第一响应者状态；临时失焦即永久退回手动。重新选择同一标签也曾无意义地增加焦点代次，令目标身份检查失效。

解锁后已通过单变量反向验证复现短暂失焦导致的失败：只把上传完成处恢复为原来的一次性焦点判断，300ms 临时窗口失焦案例在 `active=true` 下不能自动插入；恢复等待逻辑后通过。这确认了该失败路径，但不代表用户原始环境每一次偶现都只有这个原因。终端自动协议回包与真实用户输入的区分沿用既有实现，并保留专门断言。

## 修复与安全约束

- 区分真正目标变化和短暂失焦。上传完成、发送前文件复核完成后，各可等待最多约两秒，连续两次满足条件才发送。
- 仅原窗口已经在前台且第一响应者为空或窗口自身时恢复终端焦点；不激活后台应用、不抢其他输入框、不跨模态窗口或 sheet 发送。
- 继续核对 session、连接代次、输入代次、标签/分栏代次、窗口和配置。真实切换后再切回、继续输入、重连或关闭自动插入均要求人工确认。
- 同一标签重复选择不再制造焦点变化；等待焦点计入忙状态，不能被新附件替换。
- 迟到的上传进度不覆盖完成信息；已经插入的附件不能再次发送。不自动重试可能已提交的 tmux paste，避免重复插入。
- 手动跨重连插入仍需明确确认，并重新验证文件及原 tmux 目标。保留不回车和正确路径引用规则。

核心测试覆盖失活、临时脱离窗口、原窗口未知、真实切换、新输入及连接变化等身份边界。

## 解锁后补充验证

- 中英文分别覆盖本机和隔离 SSH 的九类案例：图片、Finder 文件、拖入、重复选同一标签、上传完成瞬间失焦后恢复、继续输入、手动策略、切页往返和切换终端。
- 普通终端检查实际接收文件：每次路径只出现一次，不含自动回车；重复调用插入也不会重发。
- 本机和隔离 SSH 的 tmux 在没有回车时保持等待；测试明确发送回车后，核对原窗格实际收到的完整路径恰好一次，而不只检查 `inserted` 状态。
- 单次焦点判断的反向实验退出 1，失败于短暂失焦案例；原修复已恢复并重新编译，最终完整回归退出 0。实验修改未提交。

首轮新增的接收文件检查还暴露了测试夹具的启动竞态：只等待固定 300ms，不能证明登录 Shell 已经启动 `cat`，导致检查时文件尚不存在。改为让真实 Shell 创建接收文件并返回唯一就绪标记后才发送剪贴板内容；未放宽产品焦点、输入或连接保护。
