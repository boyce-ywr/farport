# 标签分栏归属与批量删除

- 发现日期：2026-10-13；版本：0.1.4；严重程度：中（交互混淆、误操作风险）。
- 修复提交：见本文件首次引入的 Git 提交。
- 影响范围：本机/SSH 混合终端、文件来源关联、本机/SSH 文件上下文菜单。

## 现象与根因

旧 `TerminalLayout` 只有全局 primary/secondary/focused。标签实际代表单个终端，但点击别的标签会替换焦点分栏，另一个分栏一直留在屏幕上，布局重建也会改变比例。早期回归甚至把“新终端替换焦点窗格”当成正确行为，与用户要求的标签包含分栏不符。

批量文件菜单只有复制和传输，删除仅出现在单选菜单。新增批量删除的真实回归还发现：部分失败后自动预览剩余选中项，预览错误覆盖了批量删除的成功/失败统计。

## 定位与最小修复

1. 修改核心断言要求新标签不携带旧右栏，旧实现稳定失败。
2. `TerminalLayout` 改为标签列表，每个标签独立拥有分栏树、焦点、比例和最大化状态。终端连接对象不属于布局节点，不因切换而重建。
3. 视图按稳定会话 ID 放置分栏，保留隐藏标签的布局；左右/上下拆分作用于当前焦点分栏。标题对称显示来源、文件入口及关闭按钮，焦点有高亮边框。
4. 终端页的顶层标签按组展示；文件页仍列出每个会话，并可准确回到其所属标签和分栏。
5. 批量删除使用上下文菜单提供的目标集合，确认后依次执行，逐项收集失败。成功项从列表及选择移除，失败项保留；预览错误不再覆盖已有操作汇总。

## 验证

- `workbench-tests` 覆盖独立标签、嵌套分栏方向、比例/焦点保留、最大化与关闭坍缩。
- `scripts/check-pane-layout.sh` 使用真实 PTY 与隔离 SSH，反复切换八轮并逐项比较分栏尺寸和连接 ID，检查鼠标焦点、文件关联、真实菜单动作与最大化还原。
- 菜单最初被测试误判为禁用：SwiftUI 延迟构建菜单，未展开时的项目没有 target/action。按原生菜单生命周期更新后执行动作通过；尝试过的窗口焦点替代机制已撤回，没有为测试改写正常焦点机制。
- `scripts/check-file-deletion.sh` 对本机及隔离 SSH 构建原生上下文菜单，分别断言右键选中项的“删除 3 项”和未选中项的“删除”。在专用临时目录删除普通文件及嵌套目录，并通过已被移走的项目触发部分失败，检查未选文件仍存在且汇总不被预览覆盖。
- 截图位于 `.test/ui-regression/`，不提交包含本机信息的图片。菜单动作与合成鼠标测试不等于物理键盘/触控板和所有输入法验收。
- Release 后台进程另外出现 `NSApp.isActive == false`、`keyWindow == nil` 的系统焦点限制。测试明确跳过无法进行的事件派发，仍执行并检查同一工作区操作、真实 PTY、尺寸、连接及文件关联；没有修改生产焦点逻辑来伪造前台验收。

## 防止再犯

布局断言必须描述用户能观察的归属关系，不能只锁定旧实现。删除目标使用右键上下文提供的集合，不用全局选择替代；操作结果与后台预览错误要有明确优先级。
