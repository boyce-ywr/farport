# HTML 关联资源并发丢失

- 发现日期：2026-10-24。
- 严重程度：P2，HTML 页面可能显示正文，但部分图片或其他关联资源无法加载。
- 影响范围：本机和 SSH 文件的 HTML 预览，包括侧栏及双击弹窗。
- 修复提交：与本文同一提交，可用 `git log -- docs/issues/2026-10-24-HTML关联资源并发丢失.md` 定位。

## 现象与定位

需求是 HTML 除正文外，还应显示同目录和子目录内引用的图片等资源。现有 HTTP 预览服务本来允许目录内相对路径，但历史界面验收仅检查标题，未验证图片实际解码。

新增六路同时连接回归，先连接六个套接字，再发送有效资源请求。修复前稳定失败：`HTML 同时请求六个关联资源时不应丢弃请求：5`。这证明存在并发资源丢失缺口；用户没有提供具体 HTML 文件，因此不把它断言为所有资源缺失情况的唯一根因。

## 根因

`FilePreviewServer.accept` 将最多四个活动读取的限制实现为最多接受四个 TCP 连接。页面同时加载 HTML、CSS 和多张图片时，第五个连接直接关闭，没有排队等待，也没有完成资源响应。

## 修复

- 将连接接入和文件读取分开：最多保留 32 个连接，最多执行四路文件读取。
- 请求头读取完成后加入队列，读取槽位释放时继续下一个请求，不让排队请求占用后台线程或 SFTP 客户端。
- 关闭预览时清空队列并取消所有连接；请求断开时从队列移除，保留原有超时和有界读取。
- 不扩大文件访问范围：仍只允许 HTML 所在目录及子目录，保留令牌、Host/Origin、路径穿越、符号链接、CSP 和脚本信任保护。

## 验证

```sh
bash scripts/check-html-resources.sh --ssh
.build/debug/workbench-tests --preview-lifecycle-check
.build/debug/workbench-tests
```

- 修复前六路连接的第五个请求失败；修复后全部完成。
- HTTP 回归检查子目录图片的字节与 MIME、中文空格文件名、查询参数、模块 MIME、缺失文件及越界拒绝。
- 使用真实 `WKWebView` 检查本机与隔离 SSH 的侧栏、弹窗、安全模式和可信模式：13 张图片均 `complete && naturalWidth > 0`，嵌套 CSS 已应用，SVG 正常解码；页面脚本默认不执行，授权后本地普通脚本、模块导入和 JSON 读取完成。
- 生命周期回归覆盖活动读取取消、排队后继续、带排队请求停止、半包连接析构和异常连接恢复。
- 截图和带临时令牌的测试地址仅保留在 Git 忽略的 `.test/` 目录，不写入公开文档。

2026-10-24 验收结果：HTML 专项 32 项断言、本机及隔离 SSH 六个界面场景、2771 项核心断言，以及 10 轮隔离 SSH 媒体生命周期检查均通过。已人工查看生成的远端弹窗截图，关联图片实际可见；未更换已安装的应用，也未发布新安装包。

## 使用边界

使用 `./cover.png`、`images/photo.png`、`styles/report.css` 这类相对路径；CSS 中的相对路径以 CSS 文件本身所在目录为基准。不要使用指向目录外的路径、文件系统绝对路径或外部 CDN；这次没有开放它们，也没有修改 HTML 文件本身。
