## 现象与环境

- `xcode-select -p` 指向 `/Library/Developer/CommandLineTools`；当前没有可用的完整 Xcode 安装。
- Swift 为 Apple Swift 6.4，CLT 包版本 `27.0.0.0.1788430756`；系统报告 macOS 27.0.1。
- `swift build --build-system native --product SSHWorkbench -vv` 在 SwiftTerm 构建插件阶段返回：

```text
error: build planning stopped due to build-tool plugin failures
```

插件能够完成编译和链接，但没有执行到更新其工作目录中的触发文件。工具输出没有提供更具体的插件异常。

## 最小复现与定位

在忽略目录下创建不引用 Farport 或 SwiftTerm 的极小 Swift 包：一个输出固定文本的可执行目标，附带一个 `BuildToolPlugin`，其 `createBuildCommands` 只返回空数组。该包使用同一 native 构建器仍出现完全相同的插件错误。

由此确认问题不需要业务源码、SSH、Docker 或 SwiftTerm 生成器即可触发。故障边界位于当前工具链/系统执行环境的插件宿主路径，**还不能确定是 SwiftPM、CLT 运行库、系统启动约束中的哪一层**。

额外有界诊断：

1. 详细日志和此前全新 scratch 目录均复现，非单纯旧工程缓存。
2. 单次关闭 SwiftPM 子进程沙箱的诊断未使构建通过，不能把该选项当成解决方案；未修改系统防护配置。
3. 直接运行生成的插件和一个加载 `libPackagePlugin.dylib` 的独立程序出现等待；采样只看到 `_dyld_start`，不足以定位具体根因。
4. 对仅用于诊断的本地可执行文件，使用与 SwiftPM 已生成的 Debug 工具相同的 `get-task-allow` 调试签名后，直接执行可以退出，加载运行库的程序可以完成。
5. 但使用固定环境、保留该签名再次通过 SwiftPM 调度插件仍失败，包含开启和关闭插件沙箱的两种情况。**直接执行恢复不等于插件构建恢复**，不能把签名差异写成已修复根因。

所有诊断命令均有超时；没有关闭系统安全策略、修改 CLT 或第三方源码，也没有对发行应用添加调试权限。
