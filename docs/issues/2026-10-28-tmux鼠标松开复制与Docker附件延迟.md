# tmux 鼠标松开后复制失败与 Docker 图片附件延迟

- 发现日期：2026-10-28，用户在 0.1.17 发布后反馈。
- 严重程度：交互功能缺陷与性能回归点；未发现本次问题导致错误窗格写入或源文件丢失。
- 影响范围：Farport 管理的 tmux 默认鼠标拖选；本机 tmux 内已确认 Docker 目标的附件发送。
- 修复 commit：`bd2b57d`。最终回归通过，当前尚未发布新的安装包，不改变 0.1.17 的公开附件。

## 现象与复现

正常拖选文字、松开鼠标后按 `⌘C`，仍提示“tmux 当前没有可读取的选区”。另一个现象是剪贴板图片发送到 Docker 容器后很久才插入路径。

复制复现使用独立 tmux socket、合成文本和本机/回环 SSH 夹具，明确关闭 OSC52；真实调用鼠标按下、拖动、松开与 `⌘C`。旧代码稳定出现同样提示：`MouseDragEnd1Pane` 默认动作已经结束复制模式，此时再查询 `selection_present` 只能得到无选区。0.1.17 的测试通过键盘创建选区并保持不动，遗漏了用户实际的“松开鼠标”步骤。

附件基线使用独立、无网络 Docker 测试容器和非 root 用户，沿用同一张 12×12 合成 PNG；首轮从图片剪贴板发送并确认容器，第二轮从同图文件引用发送、复用绑定。摄取返回只需约 5–40 毫秒，主要延迟出现在随后串行启动的 Docker 命令，不是这一夹具的 PNG 解码。基线与优化后都使用 Debug 构建和同一机器，不能推导大图吞吐率、真实远端网络或所有 Docker 环境的耗时。

没有连接截图中的真实业务主机，也没有在日志中记录用户剪贴板正文、密钥或 Docker 凭据。

## 根因与修改

### 鼠标选区生命周期

- 在本次真实远端拖选松开时，异步读取尚未清除的选区，保存只属于本次交互的内存快照，再转发原始松开事件；不改用户的 tmux 按键配置，不拿最近的全局缓冲区代替选择。
- `⌘C` 可以等待正在进行的快照读取，也可以在 tmux 已退出复制模式后复制快照；普通复制菜单与重复复制沿用相同快照。
- 快照本身不自动写入 Mac 剪贴板；失焦、输入、连接重置、剪贴板版本变化均使其失效。新输入会先释放旧鼠标事件，等待最多两秒，超时也释放；不阻塞主线程。
- 若原有 OSC52 策略随后同步了本次选择，只有同步字节与快照完全一致、且剪贴板此前未被其他操作改动，才更新快照关联的剪贴板版本。这样超过原先两秒的“近期同步”提示窗口后仍能显式复制；不会把任意历史同步当成本次选区。
- 读取原始字节、复核选择身份与清理临时缓冲共用一次 Shell/SSH 调用，减少往返。它们仍是独立 tmux 客户端命令，并由 `&&` 保证成功顺序：不能用 tmux 内部 `;` 把 `save-buffer -` 和后续输出拼接，流式标准输出客户端的行为不同。

### Docker 附件命令开销

- 原流程先把单文件复制到另一份本机暂存目录并回读，再启动多次 Docker 命令创建目录、写文件、检查每个目录和文件。每次 `execute` 又重复检查 context、daemon 和容器身份；插入前再次做同样逐项验证。
- 单个普通文件读取为有界内存快照，检查读取前后类型、大小及修改时间，一次容器执行完成私有目录创建、内容写入、权限设置及接收用户的 SHA-256 回读。内存读取不超过已有单文件上限加一个检测字节，不再制造第二份本机暂存副本。
- 容器 ID 和原命令引用在一次 `docker inspect` 中核对；文件可读性、目录成员和哈希合并校验。每类每批最多八项，避免大目录突破命令行长度限制；保持原有 1000 条目上限。
- 上传与插入前仍验证 Docker context/Unix socket、daemon ID、容器 ID/启动状态和用户；插入前再次校验内容，保留目录成员、符号链接、非 root 读取权限、取消及等长篡改保护。没有降低内容验证强度来换取速度。

## 已测性能

以下是首轮中英文对照；最终重跑数据保存在同目录的 `docker-final.log`。

| 同一测试条件 | 修改前 | 修改后 |
| --- | --- | --- |
| 已绑定目标，同一小图再次发送到路径插入 | 18.11 / 18.47 秒 | 7.08 / 7.21 秒 |
| 首次图片剪贴板发送，含测试自动确认容器 | 24.51 / 24.45 秒 | 13.43 / 13.41 秒 |
| 两个小文件含目录：上传及校验 | 18.36 秒 | 9.00 秒 |
| 同批内容插入前再次完整校验 | 9.06 秒 | 2.17 秒 |

已绑定目标的这一用例耗时减少约 61%，不是所有图片都能“秒插”。首次确认、外部 Docker CLI、容器状态检查仍有成本；接收端 Agent 读取和识别图片不属于上述结束点。

## 保留边界与避免再犯

- 普通终端里手动嵌套的 tmux/SSH，不猜测目标归属；没有本次快照的旧选区也不读取历史缓冲。旧 tmux 开启 OSC52 而不能安全独立复制时，仍使用 Shift 拖选通道。
- 以后选区回归必须覆盖真实按下→拖动→松开→复制，不能只验证仍停留在复制模式中的键盘选区。
- 优化附件时保留输入摄取、目标确认、上传校验、最终插入各阶段的测试耗时；不能只凭剪贴板摄取很快，就认定端到端体验没有延迟。
