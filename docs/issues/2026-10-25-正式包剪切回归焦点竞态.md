# 正式包剪切回归焦点竞态

- 发现日期：2026-10-25，0.1.16 正式包发布验收期间。
- 严重程度：测试可靠性问题，阻断发布验收；没有证据表明源文件被提前删除。
- 修复提交：与本文同一提交，可通过本文件的 Git 历史定位。

## 现象与证据

正式 `.app` 经 LaunchServices 运行 `file-moves` 检查时，中英文均曾间歇失败，错误为“⌘X 未记录剪切状态或提前删除源文件”。完整分栏测试和调试构建曾通过，不能用它们覆盖本次失败。

扩充断言诊断后复现：`selection=2, rows=2, focus=false, clipboard=0, operation=nil, error=none`。这排除了选择尚未同步及复制引用写入后失败；键盘事件发生时原表格不再持有输入焦点。

## 根因

测试新建目标分栏后，工作区逻辑焦点及 `focusRequest` 指向目标分栏。旧测试仅设置源表格的 `firstResponder`，未更新工作区的焦点状态。在 SwiftUI/AppKit 异步应用目标分栏的待处理焦点请求时，测试设置的源表格焦点被覆盖，随后 ⌘X 没有作用于源分栏。

这是测试注入事件前置条件不完整，并非发现了移动引擎的提前删源。直接延长固定等待或反复重跑会掩盖竞态，不作为修复。

## 修复与验证

- 剪切检查通过工作区已有的 `focusFilePane` 入口选中源分栏，使逻辑焦点和原生焦点一致。
- 等待实际 `firstResponder`、文件选择行数及工作区焦点同时就绪后，再发送原生 ⌘X。
- 保留失败时的计数、焦点及错误诊断，不记录文件内容或凭据。
- 不修改生产快捷键拦截、剪贴板或文件移动规则，也不放宽原有测试断言。

验证使用正式包的独立中英文剪切连续回归及完整分栏回归；发行包须从包含此修复的源码重新构建，不能继续上传先前的诊断包。

2026-10-25：修复后原始正式包经 LaunchServices 连续五轮中英文剪切回归全部通过，共十次；此前诊断包再次重跑第一轮即得到 `focus=false` 的失败证据。日志分别保留于 `.test/stable-0.1.16-cut-fixed-repeat.log` 与 `.test/stable-0.1.16-cut-diagnostic-repeat.log`。
