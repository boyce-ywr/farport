# 只读监控、附件插入策略与终端右键

- 日期：2026-10-15；版本：0.1.8；修复提交：见本文件首次引入的 Git 历史。
- 范围：新增主机监控、附件策略与终端上下文菜单。监控不执行进程终止、服务重启、提权或安装组件。

## 采集与指标

参考 btop 的指标分区、Glances 的平台能力说明及 Beszel 的概览布局，未复制这些项目的实现。通过已有 SSH 或本机进程只读运行随包脚本：Linux/Termux 的 `/proc` 与系统工具、macOS 的 `sysctl`/`vm_stat`/`top`/`ps`/`netstat`/`lsof`、Windows 的 PowerShell/CIM/网络 cmdlet。

默认每两秒尝试采样，不重叠请求；慢主机由实际命令耗时决定频率。暂停/离页取消采集，曲线仅保留当前页面连接内最近十五分钟的 CPU/内存，不落盘、不后台告警。进程显示 RSS/Working Set 与两次累计 CPU 时间差，单核 100% 可超过 100%；Linux 系统 CPU 使用累计 tick 差。进程启动标识变化、主机重启、网卡计数器回绕或采样间隔过长不会沿用旧差分。

网络按网卡分别列出接收/发送字节率，不将虚拟网卡简单相加。免安装模式不提供进程级带宽，界面明确写不可用。端口优先系统工具，Linux 没有 ss 时读取 proc TCP/UDP 表；这种回退没有 PID 归属，不把缺失 PID 猜成进程。磁盘显示挂载点容量与使用率，不等同于物理盘硬件或 S.M.A.R.T.。

系统页只读取 OS/内核/架构、CPU 型号与核心、硬件型号、连接用户 ID/组/主目录/Shell。不抓进程完整命令行、环境变量、密码、密钥或硬件序列号。Windows 的 Shell 项是 PowerShell 采集环境，不能当作 SSH 默认 Shell 的检测结果。受限项显示 —，不伪装为 0。

### 长命令问题

新增 proc 端口回退后，真实 GUI 采集连续出现 `mm_send_fd: sendmsg(2): Message too long` / `mux_client_request_session: send fds failed`，短命令仍正常。相同脚本通过手工 SSH 未必每次复现，不能把所有此错误都归因于单一阈值。监控不再把整段脚本拼进 SSH exec 参数，而是用固定短命令启动解释器并从 stdin 发送脚本；保留现有复用及取消机制。修复后原 GUI 采集回归通过。脚本不会写入远端临时目录或注册服务。

## 右键与附件

普通终端默认提供复制、粘贴、全选、清除选择。粘贴复用既有图片/文件上传、多行确认机制。启用 tmux 模式只对 Farport 附着的 tmux 终端转发右键；Shift＋右键强制普通菜单。不把手工二次 SSH 或嵌套程序的 mouse reporting 当作识别 tmux 的依据。

右键真正可用还需要 tmux mouse 和对应绑定。若缺少 mouse，先请求确认，仅 `set-option -t session mouse on`，不使用 `-g` 或写配置。共享同一 session 的其他客户端也会受影响，不承诺客户端独享设置。自定义 tmux 绑定按远端配置执行。

初始测试只确认输入计数变化仍不够：原生 macOS 右键编号与终端协议的右键值不同，合成 NSEvent 也可能报告 0。直接转发不能正确打开 tmux 菜单。使用一个仅覆盖 buttonNumber 的事件包装，把右键映射到终端协议值 2，其余坐标/事件类型保留。最终测试确认终端中出现实际 tmux `Horizontal Split` 菜单文字，再用 Escape 退出，避免执行菜单中的破坏性动作。

附件策略为全局默认（自动）加主机级覆盖，旧配置字段缺省时继承；本机使用全局。新任务创建时捕获策略，之后的设置变化不改变进行中的任务。手动模式仍上传并回读，等待“插入原终端”；自动模式在校验通过且原会话/连接/输入位置/窗口身份不变时直接插入，不自动回车。失败、重连、tmux 窗格/程序变化的安全检查不放宽。

## 验证边界

- macOS 本机与隔离 Linux SSH：真实系统/用户、CPU/内存、进程、网卡、磁盘采集；暂停、取消与差分检查通过。
- 普通 NSMenu 实际右键弹出、复制/粘贴/选择动作；真实 tmux 附着、session 级 mouse 设置、其他 session/global 不变、右键菜单实际渲染通过。
- 附件手动/自动策略快照、主机覆盖、正常回读与手动插入验证通过。
- Windows 适配脚本和 UTF-16 EncodedCommand/UTF-8 BOM/CRLF 响应解析已检查，但没有 Windows 真机，不能声称已完成 Windows 运行验收。
- 用户 Termux 设备此轮连接被拒绝或超时，未进行监控实机验收；Android 权限可能禁止 `/proc/stat`、`/proc/net`、其他应用进程，界面明确说明。不会尝试 root/SELinux 绕过。
- 原始采集数据可能包含进程名称、主目录等，测试数据与截图只存 `.test/`，不上传真实本机或远端的监控记录。
