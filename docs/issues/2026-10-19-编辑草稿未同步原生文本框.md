# 恢复草稿未同步原生文本框

- 发现日期：2026-10-19。
- 严重程度：中，二期功能验收中发现，尚未发布。
- 修复 commit：包含本文的实现提交。

## 发现与根因

新增真实编辑器回归：保存时制造外部版本冲突，验证失败内容落盘；重新打开原版本后点击“恢复草稿”，检查原生编辑框实际文本，再保存并检查草稿清理。

首次运行停在“编辑框文本等于恢复内容”的断言。恢复按钮只赋值 `FileEditorBuffer.text`；`FileEditorTextView.updateNSView` 原本只更新可编辑状态，并不把该属性重新写入 `NSTextView`。因此恢复数据与可见内容脱节。

## 修复

增加明确的 `restoreDraft` 操作，经 `NSTextView.insertText` 替换完整 UTF-16 范围，同步 buffer 和动作状态、保留原生撤销并恢复焦点。没有在每次 SwiftUI 更新中重写文本，避免破坏中文输入及正在进行的编辑。

## 验证与防回归

`scripts/check-editor.sh --ssh` 覆盖真实失败草稿、外部版本不可直接恢复、重开原版本后点击恢复、实际文本更新、成功保存和恢复副本清理；同时保留连续保存、撤销/重做、工具栏剪贴板和轻提示检查。核心与工作流原生测试另覆盖草稿来源绑定及多窗口 UUID 并发保护。

修复后上述中英文、本机和隔离 SSH 原生回归全部通过，结果记录在 `.test/continue-diagnostics/editor-final.log`。这次先得到 UI 恢复失败再修复；不以只有草稿存储单测通过替代 UI 恢复验收。
