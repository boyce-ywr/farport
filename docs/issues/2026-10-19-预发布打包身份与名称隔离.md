# 预发布打包身份与名称隔离

- 发现日期：2026-10-19。
- 严重程度：中，公开分发前的包装风险；没有发现旧用户数据被删除。
- 修复 commit：包含本文的打包实现提交。

## 问题

此前本地候选包只在导出目录手工改为 0.1.11 和预览 Bundle ID，仓库清单仍是 0.1.10。包内目录依然叫 `Farport.app`，如果直接公开分发，用户拖到 Applications 时可能替换正式应用，却因为预览身份改读独立配置目录而看到空白主机列表。

## 修复

- 仓库清单统一为 0.1.11（14），正式 Bundle ID 保持不变。
- `scripts/package.sh --preview --arm64-only` 在输出清单副本中设置预览名称和身份，不再依赖导出后手工改源码。
- 预览目录、原生架构副本、DMG 暂存目录及校验清单与正式产物分离；ZIP/DMG 内均为 `Farport Preview.app`，DMG 卷名也明确为预览。
- 未知参数直接拒绝，`--preview` 与架构参数顺序不影响结果。
- GitHub 采用 Prerelease 且不设 Latest；稳定更新选择逻辑继续排除预发布。

## 验证

先运行新增打包布局夹具：旧脚本忽略预览参数，找不到预期预览目录，测试失败。修复后，名称/身份/版本、真实 ZIP 目录、DMG 暂存布局、校验清单、参数顺序和正式产物保留断言通过。

夹具只替代编译、图标和签名工具来快速验证路径规则，ZIP 与清单操作仍实际执行；它不是签名或可运行性证明。发布前仍须使用真实工具独立构建并验收生成的安装包，不能直接重新上传此前的本地候选包。

## 验收过程的附加修正

一次安装包排序回归启动后没有输出最终结果，同包单独复跑通过，尚未据此确认产品排序故障。检查发现原生测试在投递鼠标按下后先等待 80ms，才投递松开事件；如果事件跟踪先进入嵌套循环，后续主执行器任务可能无法及时投递松开。改为先顺序排入完整按下/松开事件，再等待点击结果，不改变产品排序实现或断言。发布产物须重新构建并复跑该检查。

构建排查时还曾错误地对不支持 `--help` 的生成工具使用该参数，产生 `invalidArguments` 引发的 trap；这是诊断调用错误，不是 Farport 崩溃或安全组件拦截。改为源码定义的“仓库目录、输出文件”两个参数后，生成工具正常执行。诊断探针输出未写入实际构建生成目录，正式编译仍使用 SwiftPM 原有插件和沙盒。

最终源码固定于 `21940b0`，独立构建环境按该提交重新编译，不使用上一份候选安装包。最终 2481 项核心断言、中英文十二组正常 LaunchServices 安装包回归和无 QA 参数的日常启动全部通过；旧候选文件留在私有测试目录，没有上传为公开发布附件。

2026-10-19 完成发布：`v0.1.11` 的远端标签精确指向该源码提交，五个附件在草稿阶段回下载并逐一核对 SHA-256 后才转为预发布。发布后核对 `draft=false`、`prerelease=true`，Latest 仍为 `v0.1.9`。没有修改旧 Release 或覆盖旧附件。
