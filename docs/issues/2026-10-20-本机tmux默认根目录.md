# 本机 tmux 新会话默认进入根目录

- 发现日期：2026-10-20。
- 严重程度：中；不导致数据丢失，但新会话落入意外目录会干扰日常命令和文件操作。
- 影响范围：Farport 创建的本机 tmux 会话，以及应用内本机 tmux 新建窗口/分割。普通本机登录 Shell 已显式设置工作目录，未发现同一缺陷。
- 修复提交：与本文一同提交，可用 `git log -1 -- Sources/OpenSSHBackend/TmuxService.swift` 定位；未覆盖已发布的 `v0.1.12` 标签或附件，本修复尚未发布。

## 现象与复现

用户报告本机终端中的 tmux 打开后 `pwd` 为 `/`，期望从用户主目录开始。使用唯一 `-L` socket、`-f /dev/null` 和独立临时目录创建测试服务，不接触用户正在使用的 tmux 服务或配置：

```sh
bash scripts/check-local-tmux-directory.sh
```

修复前，同一生产 `TmuxService.create(name:)` 从不同应用目录运行：应用 cwd 为 `/` 时新窗格为 `/`；应用 cwd 为仓库目录时新窗格也落在仓库目录。两种情况都没有进入主目录。测试预先启动了独立服务，因此排除了仅首次 tmux 服务启动、用户配置和旧会话恢复造成的混淆。

## 根因

`LocalShellConfiguration` 正确给出了用户主目录，并设置了 `HOME`、`PWD`。普通本机 PTY 启动会传递 `currentDirectory`，但 `TmuxService.runShell` 只使用了配置中的环境变量，未将目录传给 `ProcessRunner`，而 `ProcessRunner` 原来没有工作目录参数。

结果是 `/bin/sh -c tmux ...` 继承 Farport 进程的真实 cwd。设置环境变量 `PWD` 不会执行 `chdir`；tmux 新会话因此使用客户端进程的实际目录。应用从图形界面启动且 cwd 为 `/` 时就出现用户报告的现象。

仅修正默认 cwd 后，新窗口会退回主目录而不是已有项目目录。该行为由新回归明确捕获，因此本机 `new-window` 和 `split-window` 另外使用 `-c '#{pane_current_path}'` 固定为目标窗格目录，避免继承应用或其他会话目录。

## 修复

- `ProcessRunner.run` 新增可选 `currentDirectory: URL?`，通过 `Process.currentDirectoryURL` 设置，只作用于被创建的子进程；默认调用行为不变，不使用全局 `chdir`。
- `TmuxService` 仅在本机分支传入主目录，保留环境清理。远端仍走原有 SSH 命令，不把本机路径发送给远端。
- 本机新窗口/分割以 tmux 的目标路径格式取目录，不拼接用户目录文本；含中文、空格、单引号、美元符号和分号的项目路径均实际验证。
- 附着旧会话不发送 `cd`，不结束用户进程、不修改 tmux 全局配置。已处于 `/` 的旧窗格仍会保留该目录，用户可在 Shell 空闲时自行执行 `cd "$HOME"`。

## 验证

- 红绿回归：修复前从 `/` 和仓库目录启动均失败；修复后从 `/` 与独立测试目录启动均通过。真实 `pane_current_path` 验证新会话主目录、新窗口/分割继承目录、新建其他会话和原窗格不变。
- 核心回归新增真实相对文件读取、特殊字符目录、父进程 cwd 不变、无效目录拒绝检查，合计 **2511 项核心断言通过**；不是只比较 `PWD` 环境变量。
- 普通本机 PTY 回归改为检查 `/bin/pwd -P`，从 `/` 启动新版开发程序，交互登录 Shell、真实主目录、退出重开、多标签/分屏和本机/SSH 混合分屏通过。
- 根目录启动的隔离 tmux 回归另外连续三轮通过；**19 组真实 SSH 集成检查通过**，包括远端 tmux、跨主机传输、转发和断线续传。集成故障注入与界面检查顺序运行，避免影响共享测试服务。
- 复现与验证日志保存在 `.test/continue-diagnostics/local-tmux-*.log`，不提交用户名、测试凭据或用户原始截图。

## 防止再犯

后台进程的环境变量与真实工作目录必须分别验证。涉及 tmux 的测试使用唯一服务，既覆盖新建，也覆盖已有项目窗格；GUI 启动场景不能只从代码仓库目录跑测试。升级不自动重置用户既有 tmux 会话目录。
