# Agent 会话目标隔离与外层标签按键

- 日期：2026-10-21；范围：0.1.14 开发预览，不修改已发布的 0.1.13（18）发行二进制。
- 严重程度：中。若恢复命令、cwd、容器或按键目标错误，可能影响用户正在运行的工作。
- 实现提交：与本文一同提交，`git log -1 -- Sources/WorkbenchApp/AgentSessionsView.swift` 可查询；研究方案另见 `docs/research/2026-10-20-terminal-tabs-agent-sessions-design.md`。

## 需求与实现边界

用户要求快捷切换 Farport Tab、快速找到并进入当前设备上的 Claude Code/Codex/Pi 工作。核心约束是不能占用内部 tmux 按键，不把 `cd` 或恢复命令注入正在工作的 Agent，不把历史文件当作当前运行进程。

Tab 新组合复用原标签动作，精确限定 Command+Option 方向键/数字/J，并保留旧 Command+Shift 方括号。文本输入、组字、sheet、modal 不抢焦点；切换标签之后对应 keyUp 在原窗口和新窗口都不得送进另一个终端。增强键盘协议可报告修饰键，所以对尚未判定动作的修饰键事件暂存：普通按键前按原序给原终端，导航时消费整个组合及释放事件，而不是只处理 keyDown。

会话面板固定执行目标，只在用户允许时读取历史。首版不启动新 app-server、不隐式安装 SDK，而采用带大小/时间/层级限制的已知 JSONL 元数据适配；未知格式用原生选择器。支持的记录不是“全部历史”，文件修改时间不是运行状态。这是对原研究中 SDK/app-server 优先方案的可交付降级，不将其描述为完整官方接口集成。

## 排查中发现并修正的点

1. 原容器测试用 `ProcessRunner` 普通管道执行 `docker exec -it`，返回 `the input device is not a TTY`。将同一准备好的生产启动命令放入独立 tmux TTY，再检查实际 `/tmp` 输出；没有通过去掉生产 `-t` 来掩盖问题。
2. 新建测试 tmux 窗口以 `-t docker` 意外命中已有 index 0，改为 `-t docker:` 明确分配下一窗口；只操作唯一隔离测试服务。
3. 只查文件存在会赶在后台程序写完参数前读取空文件，改为等待结果中预期参数，再核对 cwd/参数和原 PTY 零输入。
4. 历史 ID 同名可能存在于不同配置根，记录主键纳入 dataRoot，恢复时固定对应 CODEX_HOME/CLAUDE_CONFIG_DIR/PI 会话目录；启动前重核该记录仍属于当前用户工具根，不跟随伪造的叶子符号链接或 FIFO。
5. 取消/刷新后的异步结果可能晚到，面板使用取消标记和请求世代，旧请求不得重新覆盖状态或启动工具。容器目标在前台进程改变、连接配置改变后不能继续复用；管理器新建的 Docker 标签重新识别自身前台进程而非借旧窗格身份。
6. Docker 执行模块对非零退出直接抛错，原 `command -v python3` 无法进入无 Python 降级分支；改为成功返回有界探测标记，再保留三工具原生启动入口。隔离容器临时移除/恢复 Python 的回归覆盖该分支，不修改用户容器。
7. 重新附着已启动的 Agent tmux 不应再次执行恢复命令；丢失 tmux 会话报错，不重建、不重放。普通 PTY Agent 也禁用自动重连重放，恢复由用户明确触发。

## 回归

```sh
bash scripts/check-agent-workspace.sh
bash scripts/check-agent-workspace.sh --models
.build/debug/workbench-tests --agent-session-check
.build/debug/workbench-tests --agent-session-ssh .test/app
SWB_QA_DOCKER_ENDPOINT_MODE=host bash scripts/check-docker-attachments.sh
```

- 首轮中英文前台检查已验证导航、keyDown/keyUp/连发、文本框例外、面板快捷键与新标签隔离；随后增加 report-all 修饰键覆盖和目标安全收尾，最终前台检查仍需要解锁，不能沿用首轮结果宣称最新版全通过。
- 非前台处理中英文验证新 tmux、真实 cwd/argv、当前工作窗格零输入、运行登记、重新附着不重跑、取消和旧会话消失。
- 核心夹具包含三工具历史、危险路径、巨长头行、畸形 payload、符号链接、工具配置根和会话不存在；不返回测试中的聊天/系统指令字段，不读取真实用户历史。
- 两个隔离 SSH 服务验证三工具的启动参数和真实 cwd；独立 Docker 容器验证目标 UID、无 Python 降级和真实 TTY cwd。工具执行器使用可观测测试夹具，不能据此声称真实 Claude/Codex/Pi 的模型上下文已端到端恢复。
- 详细结果在 `docs/releases/0.1.14-preview.md`；证据保存到 `.test/continue-diagnostics/agent-*.log`，不纳入 Git。

## 不包含的能力

不全文搜索会话、不扫描所有保存主机、不检测任意外部终端中的所有同会话进程；不跟随 Docker 内二次 SSH/su。没有可信目标时需选择实际连接。工具自定义配置路径、归档/分支/旧格式不保证全部覆盖；原生选择器保留，不以解析失败伪装空历史。
