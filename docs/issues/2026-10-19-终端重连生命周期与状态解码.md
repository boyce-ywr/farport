# 终端重连生命周期与退出状态解码

- 发现日期：2026-10-19。
- 严重程度：高，影响 SSH 中断恢复、手动重连及连接状态展示。
- 修复 commit：包含本文的实现提交，可用 `git log --all -- docs/issues/2026-10-19-终端重连生命周期与状态解码.md` 定位。

## 现象与定位

用户报告切换标签后返回，连接已断开。隔离 SSH 回归还确定复现了另一个问题：对运行中的连接主动重连，会停在等待旧进程退出阶段。

固定版本 SwiftTerm 的 `LocalProcess.terminate()` 会取消进程退出监视器；原实现调用它以后，又依赖退出回调启动新连接，因而可能永远等不到回调。另一个错误是将回调参数当作普通退出码：macOS 回传的是原始 `waitpid` 状态，SSH 的退出码 255 对应原始值 65280，退出码 1 对应 256。

**尚未确定用户那次切标签断线的原始原因。** 当前隔离环境的后台空闲测试不能证明 App Nap、Wi-Fi 或服务端策略是那次断线的根因。

## 修复

- 仅对本会话拥有的正数 SSH PID 发终止信号，保留退出监视器；观察到退出以后，才启动唯一的新连接。
- 原始退出回调先同步记录已退出，防止主线程回调尚未消费时继续对已回收 PID 发信号。关闭中的会话临时保活，超时强停仍核对 PID、连接代次及退出标记。
- 解码 `waitpid` 状态，正常远端退出不自动重建；网络错误按 1、2、4、8、15、30 秒退避并加入小幅抖动，稳定运行 30 秒后重置退避。
- 保留 `ServerAliveInterval=15`、`ServerAliveCountMax=3`。减少后台 App Nap 影响但允许正常系统休眠；网络变化及唤醒不强拆仍健康的连接。
- 自动恢复严格校验指纹，只使用无需新交互的已授权凭据；身份、指纹、配置及未知错误暂停，交给用户主动验证。
- 原 tmux 只重新附着，不创建替代会话、不重放命令、不抢前台标签。状态栏、分栏菜单及 `⌘⇧R` 提供手动恢复；普通 Shell 重连提醒可能终止原任务。
- 连接诊断只包含时间、事件、PID、退出状态，不记录主机、账户、凭据或终端正文。

## 验证与剩余限制

`scripts/check-connection-stability.sh manual|stability|recovery` 创建并仅操作带本轮标签的独占测试容器：

- 修改前手动重连失败；修改后获得新 PID，真实命令执行成功。
- 切标签和文件页后后台空闲 70 秒，连接代次、SSH PID、tmux pane PID 及长任务保持。
- 断开服务器连接后自动恢复原 tmux；暂停自动恢复后可手动恢复。
- 暂停容器内 sshd 模拟无 TCP 关闭通知的黑洞，本轮约 59 秒检测到中断并恢复，不承诺固定 45 秒上限。
- 无缓存凭据及指纹询问静默拒绝；错误指纹不被接受，恢复正确指纹后可手动连接；正常退出不自动重建。

核心和原生回归不替代用户实际网络长期观察，也不替代已安装应用的启动验收。原始日志仅保存在忽略的 `.test/continue-diagnostics/`。
