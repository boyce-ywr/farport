# 工作工具首批使用说明

日期：2026-10-19。这是本地开发预览的功能说明，不代表新的稳定版已经发布。

## 入口

- 主机选择器旁的四格“工作工具”菜单：工作区恢复、常用命令、目录联动、目录收藏和远程 Mac 桌面。
- `⌘⇧P`：常用命令；`⌘⇧O`：定位终端当前目录。
- 主机右键菜单：“打开远程 Mac 桌面…”。

## 工作区恢复

标签、分栏比例、焦点、主机引用及明确附着的 tmux 标识会自动保存，最多保留十个窗口记录。重开应用后，在空窗口的“恢复工作区”中选择记录；有终端的窗口不会被替换。

恢复的是布局与连接意图，不是命令输出、未保存编辑或远端进程。显示终端时才按原有连接流程启动；不会重放历史命令、创建替代 tmux、自动恢复桌面通道。已删除或连接配置已变化的主机会跳过。多个窗口恢复同一记录后分别保存，不共同覆盖同一窗口标识。

## 常用命令

手动添加名称、单行命令、标签和可选的适用主机。搜索可匹配名称、标签、正文；保存后可以编辑或删除。

“插入终端，不回车”只向打开面板时选中的同一连接插入文字，不读取或覆盖系统剪贴板。换了标签、连接已经重连/断开、适用主机不匹配或处于备用屏幕的全屏程序时拒绝插入。仍应确认当前程序是 Shell 提示符；没有自动回车不意味着任意终端程序都不会处理输入。

不自动采集输入或历史，不保存桌面密码；不要手动将密码加入片段。换行、终端控制字符和过长命令均拒绝保存/插入。

## 目录联动与收藏

“定位终端当前目录”消费终端已经报告的 OSC 7 文件 URI；可选择让当前终端对应的文件区继续跟随。不会猜提示符或修改远端 Shell 配置。

报告必须是绝对路径，并且主机匹配：远端与当前 SSH 配置的地址匹配，本机与本机名称/loopback 匹配。账号、端口、查询参数、片段标记、无效编码及控制字符会被拒绝。没有报告、主机别名不匹配、tmux 等情况仍需手动浏览；本版不声称覆盖所有 Shell、嵌套 SSH 或 tmux 的自动目录跟随。

文件页面可收藏当前目录。收藏保存主机连接标识，主机被删除或连接配置变化时不会悄悄应用到另一个目标；可移除旧收藏再重新添加。

## 远程 Mac 桌面：实验功能

先选择正确的主机，再打开桌面入口。默认走 SSH：SSH 主机就是目标 Mac 时保留 `127.0.0.1:5900`；如果 SSH 主机只是网关，则填写它可访问的目标 Mac 地址。

Farport 用 Network.framework 直接绑定 `127.0.0.1` 的系统分配端口，再通过独立的 OpenSSH `-W` 标准输入/输出通道转发。不是先释放一个空闲端口再争抢，也不继承额外的端口转发或 agent 转发。数据按有限块传递并等待发送完成；不解析或存储桌面认证内容。

macOS 自带的 Screen Sharing 负责认证、显示和输入。首期目标是目标 Mac 已授权的系统用户名密码，而非 iCloud 登录；Farport 不会自动开启共享服务、修改 Remote Management、填入密码或要求另设传统 VNC 共享密码。

须注意：

- 系统窗口显示的是本机转发地址，必须核对 Farport 中显示的真实目标；启动系统客户端不等于桌面已经登录。
- 关闭终端或桌面设置面板不会关闭桌面通道；运行记录里的“断开通道”才会关闭它，退出 Farport 也会关闭。
- 可信 LAN/VPN 直连是显式选项，不自动绕过 SSH；直连窗口由系统客户端独立管理。
- 普通 SSH TCP 通道只按标准屏幕共享设计，不承诺苹果高性能模式。
- 已有测试只覆盖本地数据通道、独立 SSH 转发、生命周期和界面。系统账户登录、锁屏、中文输入、多显示器、多主机钥匙串身份仍需要真实 Mac 验收，因此保留实验标识。

## 数据与预览包

工作工具写入当前工作区的 `workspace-tools.json`，沿用私有目录和文件权限；读取失败不会覆盖原文件。记录包含本地配置、连接标识、用户主动保存的命令和路径，应视为私人数据。

目前没有可交付的新安装包：独立 Release 完成了原生回归，但单架构和通用 `.app` 均被系统以 SIGKILL 终止，正常 LaunchServices 启动也未完成验收。失败产物已撤到私有 `.test/` 目录，没有覆盖正式应用或提供替代启动器绕过安装验收。

日志出现 AMFI `-423`（ad-hoc 或未知证书链），本机有效签名身份为零；这指向签名/准入边界，但不足以唯一断定 SIGKILL 根因。需要合法签名、公证与平台准入检查后重新验收。代码已为 `local.sshworkbench.preview` 预览包隔离数据目录，避免将来验证时与正式应用共用传输记录。

此外，将实现提交单独导出后的干净构建停在 SwiftTerm 构建工具插件阶段，未进入核心测试；现有整合工作区的通过结果不能替代这项验证。具体命令、阶段和限制见 `issues/2026-10-19-工作工具输入与恢复边界.md`。

## 可复现验证

```sh
swift build --build-system native
.build/debug/workbench-tests --workspace-tools-check
.build/debug/workbench-tests --screen-sharing-check
.build/debug/workbench-tests --screen-sharing-ssh "$PWD/.test/app"
bash scripts/check-workspace-tools.sh
FARPORT_APP="$PWD/.build/debug/SSHWorkbench" bash scripts/check-copy-and-sort.sh --ssh
```

SSH 项仅接受隔离的本机测试服务器，不会自动使用生产主机。UI 脚本为每种语言创建独立数据目录，截图留在忽略的 `.test/` 下；不会将这些私人运行资料发布到仓库。
